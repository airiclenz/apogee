Architecture review · apogee

Hoisting the TUI's Host Half

The engine/TUI seam holds — internal/agent never imports internal/tui, the TUI reaches the engine only through tui.Engine, and headless.go and daemon.go drive the same engine with zero tui. references. What this review finds is host behaviour that lives on the wrong side of that seam: Driver-neutral rules that only the TUI can reach, spelled again by hand in every other Driver.

Group A

Rules that live in internal/tui and are re-spelled elsewhere

Every candidate here has a sibling internal/<pkg> that already owns half the concept. The pattern is the one internal/sanitize and internal/format already ratified: the library owns the rule, the TUI keeps a three-line delegate as its grep-able vocabulary.

Top recommendation

A1 · one session-title rule, then A2 and A3 in the same plan

A1 is the smallest move with the highest evidence — four spellings, two of them apologising in comments, and the target package already holds the constants. It proves the sibling-package pattern at −70 lines; A2 repeats it; A3 is the first hoist that gives another Driver a capability it lacks. A6 is the biggest payoff but needs the neutral entry model first — a plan of its own.
