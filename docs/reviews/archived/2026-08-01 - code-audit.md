# Code Review — Apogee (whole repository) — 2026-08-01

**Scope:** the full Go tree — the root facade, `cmd/apogee`, and every `internal/` package (agent loop, mechanisms, tools, processing, platform/security/confinement, provider, domain, session, skills, present, library, MCP, TUI), tests included.
**Mission:** Apogee is a cross-platform terminal coding agent that owns the full agentic loop for small, locally hosted LLMs (~4B–35B) on any OpenAI-compatible server, layering gated self-regulating Mechanisms inside that loop without ever making a model perform worse than with Mechanisms off.
**Files reviewed:** 494

## Executive Summary

The most urgent defect is a lost-update race on the session record: the auto-title rename is a read-modify-write of the whole file that runs on a different goroutine from the per-Turn save, and Bubble Tea *batches the two together* after every save — a probe measured a whole Turn silently rolled off disk in 25% of runs, breaking ADR 0022's "a crash loses at most one Turn" with default configuration. Overall health is high: the architecture matches its ADRs closely, the concurrency contracts are unusually well documented and mostly enforced, and the test suite is genuinely strong (adversarial cases, wire-level assertions, dedicated race tests, always-on `-race`). The systemic problem that cuts across the most findings is **uniformity, not design**: several security disciplines the project invented and applies almost everywhere are enforced per call site instead of at a seam, so the one or two producers that were added later slipped through — the workspace fence never reached `grep`'s walk, `view_diff`, or the context-file loader; terminal-escape stripping never reached tool calls, tool results, or `/skills` notes; the `force` flag on an approval is honoured on the cache read but not the cache write. A second, smaller cluster is live state that stops composing one seam out — sub-agent mode tightening stops at depth 1, the Plan tool menu and the resolution ladder key on different facts, the heartbeat generation guard is not bumped on one path. The Linux confinement backend also cannot build its ruleset at all on ABI 1–2 kernels (Ubuntu 22.04, Debian 12, RHEL 9), which makes Auto mode non-functional on the most common LTS hosts while still reporting itself capable.

## Intent & Architecture Findings

### High — Sub-agent mode tightening stops composing at depth 1 `[Intent + Correctness]`

- **Where:** `internal/agent/subagent.go:141`
- **What:** `newChildAgent` sets `child.liveMode = a.Mode` — the direct parent's *own* mode accessor. A sub-agent's own `mode` field is frozen at spawn (`SetMode` is only ever called by the host on the top-level Agent), so for a grandchild `effectiveMode() = TighterMode(spawnMode, depth1Parent.Mode())` reads a value that can never change.
- **Why it matters:** the user runs Auto, the model delegates, the depth-1 child delegates again, and the user Shift+Tabs down to Plan mid-run. The depth-1 child's next call refuses, but the depth-2 grandchild keeps auto-running writes and subprocesses until its Exchange ends — its effective privileges now exceed its parent's, the exact tighten-direction failure ADR 0005/0013 forbid and the bundle invariant "sub-agent privileges are always ≤ the parent's" states. Tests cover depth 1 only (`setmode_test.go:65`); the chain is untested.
- **Fix:** capture the parent's *effective* view — `child.liveMode = a.effectiveMode` — which composes transitively and stays tighten-only and race-free through the same accessors. Add a depth-2 test. Then correct ADR 0013's "Post-v1 realisation" section, which says "captures the parent's `modeMu`-guarded `Mode` accessor": the ADR text itself encodes the hole and should say *effective* mode.

### High — The landlock ruleset requests an ABI-3 access right while advertising ABI-1 support `[Intent + Correctness + Security]`

- **Where:** `internal/platform/landlock_linux.go:85` (mask), `:204` (ruleset creation), `:63`/`:66` (the claim)
- **What:** `landlockFSWriteAccess` unconditionally includes `LANDLOCK_ACCESS_FS_TRUNCATE`, which the kernel only knows from ABI 3 (Linux 6.2), and `applyLandlock` hands that mask to `landlock_create_ruleset` with no ABI-based masking. The kernel returns EINVAL for a `handled_access_fs` containing unknown rights, so the `__confined-exec` child dies before exec. Meanwhile `landlockABIFSWrite = 1` keeps `Capabilities()` reporting `FSWrite: true`, so dispatch *confines* instead of gating.
- **Why it matters:** on Ubuntu 22.04 (5.15 → ABI 1), Debian 12 (6.1 → ABI 2) and RHEL 9 (5.14 → ABI 1) — three of the most common Linux hosts, and exactly the kernels ADR 0012 widened Auto to reach — every confined tool call fails with "landlock_create_ruleset: invalid argument". It fails closed (nothing runs unfenced) but Auto becomes a mode in which nothing runs, breaking the confinement contract's §5 capability-honesty rule and the claims at `docs/design/confinement-execution-contract.md:471` and ADR 0012:77/111. It is invisible on the 6.18 dev host, and `TestLandlockCapabilitiesHonest` pins `FSWrite=true` for `abi1_kernel_5_13` without ever exercising `applyLandlock` below ABI 3.
- **Fix:** derive the handled and per-rule allowed access masks from the probed ABI in both `applyLandlock` and `allowWriteBeneath` — drop `TRUNCATE` below ABI 3 — as a pure `accessMaskForABI(abi)` with a table test pinning ABI 1/2/3. While there, *add* `LANDLOCK_ACCESS_FS_REFER` at ABI ≥ 2: landlock denies cross-directory rename/link by default even when the right is unhandled, so today a confined child cannot `git mv` or do atomic mkdir-then-rename anywhere, including wholly inside the workspace.

### High — The tighten-only project rule merge can be dissolved by tier promotion `[Intent + Correctness + Security]`

- **Where:** `internal/security/rules.go:147`
- **What:** in `MergeDangerousRules`, a same-ID project add carrying a strictly higher Tier replaces the entire rule (`out[idx] = r`) — Pattern and Reason included. A hostile repo's project config can therefore ship `{ID: "sudo-escalation", Tier: TierHardRefuse, Pattern: "zzz-never-fires"}`: the tier check passes, the shipped pattern is discarded, and `sudo` / `curl … | bash` then match nothing.
- **Why it matters:** this is precisely the replace-by-ID-with-a-never-matching-pattern attack the function's own contract says it prevents ("a project can never loosen or dissolve an existing rule", `rules.go:131`), and it contradicts `internal/security/doc.go:27` and ADR 0012 D6 ("project config may only add"). Only Tier-1 rules are actually protected, because nothing outranks `TierHardRefuse`. `TestMergeDangerousRules_ProjectAddTightensInPlace` *asserts* the pattern replacement as intended and the floor-preservation test covers Tier-1 only, so the tests encode the loophole. It is latent today — `MergeDangerousRules` has no production caller yet, guards are always `NewDefaultGuards()` — but TODO.md L1 promises a wiring-time re-verification that would pass against these tests.
- **Fix:** on a same-ID strictly-stricter project add, keep *both* rules rather than replacing (Inspect already reports the strictest matching rule, so coexistence tightens without shrinking coverage). Update the two tests, including a tier-promotion case in the dissolve test.

### High — `autofix` spawns an external formatter outside every execution guard `[Intent + Security + Concurrency]`

- **Where:** `internal/mechanisms/autofix.go:237` (spawn), `:211` (prettier rungs), `:188` (`sanitizePath`), `:129`/`:234` (context)
- **What:** `runExternalFormatter` uses a bare `exec.CommandContext`. The only site that calls `domain.Confiner.Confine` is `internal/tools/exec_common.go:138`, and approval + `guards.PreExecute` run in `internal/agent/dispatch.go:52/60` — *after* post-response hooks. Post-response dispatch has no mode gate at all, so this fires in Plan mode, which `CONTEXT.md:208` defines as "read-only; no writes or command execution". The command also sets no `cmd.WaitDelay` and derives its timeout from `context.Background()`.
- **Why it matters:** two separate consequences from one seam. (1) Security: a malicious repo plus the prettier rungs is arbitrary code execution as the user — prettier resolves configuration by walking up from `--stdin-filepath` and `require()`s `.prettierrc.js` / `prettier.config.js` / `.prettierrc.cjs` and any plugin they name, and `sanitizePath` rejects only NUL/CR/LF, so the model freely chooses (including absolutely) which directory that resolution starts from. No approval, no confinement, no dangerous-action guard, no mode ladder. (2) Liveness: on timeout Go kills only the direct child, so a wrapper-shaped formatter (`prettier.cmd` → node, `black.exe` → python, any shell shim) leaves a grandchild holding the inherited pipes and `cmd.Run()` never returns — the single-goroutine Agent and the TUI worker freeze permanently mid-Turn. This is the one subprocess spawn in the tree that skips the process-group teardown discipline `internal/tools` applies everywhere else.
- **Fix:** run the formatter through the same execution seam tools use (`Confine` with the workspace box) and refuse it outright in Plan mode; drop the two prettier rungs, or at minimum substitute a workspace-relative basename derived from the extension instead of the model's path. Set `cmd.WaitDelay = formatterTimeout` and derive the timeout context from the hook's ctx so a user cancel stops an in-flight formatter. Make the timeout injectable (a field on `autofixMechanism`) so the kill path becomes testable — `autofix_test.go:23` currently raises it to 60s globally, which makes it untestable as designed.

### Medium — Repo-supplied skills outrank the user's global library and shadow it silently `[Intent + Security]`

- **Where:** `internal/skills/load.go:66` (source order), `internal/skills/catalog.go:36` (`set`)
- **What:** `sourceDirs` returns `[<home>/skills, <workspace>/.apogee/skills, <workspace>/skills]` in *increasing* priority and `Catalog.set` is a plain last-writer-wins map assignment. `<workspace>/.apogee/skills` is scanned unconditionally — the `use-project-skills` flag only guards the bare `skills/` dir — so repo-authored content outranks the user's own global library on an ID collision, and nothing is recorded in `Catalog.Skipped`.
- **Why it matters:** a hostile repo ships `.apogee/skills/code-review/SKILL.md` carrying the DisplayName and Summary of the user's real skill and an attacker-authored body. The user clones, runs apogee, types `/code-review`, and the repo's instructions are prepended to the turn with full agent authority — in Auto, that is arbitrary command execution. The picker shows exactly one row and no collision notice, so the substitution is invisible. This inverts the project's own repo-trust posture ("project config may only tighten") and also breaks `internal/skills/doc.go:23-25` ("soft must not mean silent, or a broken skill is indistinguishable from an absent one") for same-source collisions too — two folders in one source dir with colliding IDs lose one silently. **This warrants revisiting the load-order decision recorded in `internal/skills/load.go`**, which documents the order as oracle parity without weighing the workspace-over-global consequence.
- **Fix:** let the global library win a cross-source ID collision (or keep workspace priority only among the workspace sources), and record every shadowed or replaced pair as a `SkipError` so `/skills` names it.

## Critical & High Findings

### Critical — Session-record writes are unserialized, so a title write can roll a whole Turn off disk `[Concurrency, cross-validated]`

- **Where:** `internal/tui/autotitle.go:176` (also `:203`, `:244`), `internal/tui/sessions.go:281`/`:292`/`:310`, `internal/tui/model.go:1514`/`1541-1549`, `internal/session/store.go:179`
- **What:** `applyTitle` / `flushPendingTitle` / `runRename` all end in `setSessionTitle`, whose `tea.Cmd` calls `SessionHost.Rename` on its own goroutine. `Store.Rename` is a read-modify-write of the whole record (Load → set `Meta.Title` → Save) while the per-Turn `saveCmd` overwrites the same file wholesale. Nothing serialises them: `sessionHost` holds its mutex only around the in-memory active identity, never around file I/O, and the rename Cmd is not part of the `saveBusy`/`pendingSave` single-flight. They are in fact *scheduled to collide* — `saveComplete` returns `tea.Batch(m.flushPendingTitle(), m.scheduleSave(*m.pendingSave))`, and Bubble Tea runs batch members on separate goroutines. `deleteSession` has the same shape: it can remove a record an already-dispatched save then re-creates.
- **Why it matters:** `auto-title:` is on by default. Turn 1 completes → save A dispatched; Turn 2 coalesces into `pendingSave`; save A's completion batches the title flush beside the coalesced save; the rename re-loads the pre-B record, stamps the title, and writes it back over B. The stored record — engine `Session` *and* TUI transcript blob — reverts one Turn, breaking ADR 0022's "a crash loses at most one Turn". A probe over `internal/session.Store` (concurrent `Save(turn2)` + `Rename`) lost the newer payload in **50/200 runs (25%)**. A `/rename` typed during any per-Turn save is the same race with no auto-title involved. `go test -race` cannot see it: the lost update is over a file, and the TUI test fake serialises every host call under one mutex.
- **Fix:** give record writes one serialization point. Carry the pending title on `savePayload` and let `SessionHost.Save` apply it (or queue the Rename/Delete Cmds behind `saveBusy` exactly as `pendingSave` is queued), and belt-and-braces guard `session.Store`'s Save/Rename/Delete with a store mutex so the read-modify-write is atomic against a concurrent Save. Also fix the adjacent drop: `applyTitle` branches on `ActiveID()`, which becomes non-empty *before* the first atomic write lands, so a title answering in that window takes the "record exists" branch, `store.Load` fails with ENOENT, and the title is discarded silently.

### High — Terminal-escape stripping is enforced per call site, and several untrusted producers were missed `[Security, cross-validated]`

- **Where:** `internal/tui/transcript.go:431` (also `:416`, `:485`, `:136`), `internal/tui/toolpresent.go:303`, `internal/tui/skills.go:51`, `internal/tui/activity.go:127-133`, `internal/tui/autocomplete.go:350`/`:406`/`:426`, `internal/tui/sessions.go:370`, `internal/tui/model.go:1885`
- **What:** `stripEscapes` is applied at individual producers (streamed tokens, canonical messages, skill chips, picker cells, approval prompts) but not at the transcript boundary, and the enumeration is incomplete. Unstripped today: `addToolCall`→`presentToolCall` (target pulled verbatim from the model's JSON arguments), `addToolResult`→`enrichWithResult` (summary and details built from `result.Content`), `addError`, the `/skills` catalogue note (repo SKILL.md `DisplayName`/`Summary`, and the YAML error text for refused files), the activity status label, the autocomplete dropdown's skill and file rows, resume notes carrying `session.Meta.Title`, and the automatic rebind note carrying the server-advertised model id.
- **Why it matters:** the frame is rendered through ultraviolet's cell buffer, which drops most zero-width sequences but **deliberately honours OSC 8 hyperlinks** — and the link state is never reset across cells or newlines, so one unterminated OSC 8 opener turns every remaining cell of the frame (the transcript below it, the input box, the footer) into a clickable link to an attacker URL. Both named attackers reach it with no user action beyond normal use: a malicious repo controls the first line of any file the model reads (`firstLineDetail`), any command's first output line (`outputDetail`), skill front matter, and workspace filenames; a hostile model controls tool-call arguments, and `foldActivity` paints the label the moment a call is *announced*, before any gate runs. This is directly weaponised against ADR 0019, whose rung-0 mechanism is "cmd+click the path we print". Verified in-package: an OSC 52 payload fed through `ToolCallEvent`/`ToolResultEvent`/`ErrorEvent` survives `renderLines`.
- **Fix:** strip at the seam rather than per producer — `stripEscapes` inside `addNote`/`addError` and inside `presentToolCall`/`enrichWithResult` (target, summary, every detail line), which also covers the orphan-result branch. Wrap the remaining non-transcript producers at their one function each (`toolActivityLabel`, the three `popupRow` builders in `autocomplete.go`). Then extend `TestTranscriptStripsTerminalEscapes`, which today pins only the three paths that already pass.

### High — `grep` follows workspace symlinks out of the workspace `[Security + Correctness, cross-validated]`

- **Where:** `internal/tools/grep.go:144` (walk), `:169-177` (`searchFile`)
- **What:** the directory walk yields every non-directory entry, symlinks included, and `searchFile` opens it with a plain `os.Stat`/`os.Open` on `filepath.Join(root, rel)` — no `resolveInRoot`, no pinned root. Only the top-level `path` argument is fenced (`grep.go:96`), so the same logical operation is handled two different ways inside one tool.
- **Why it matters:** git stores symlinks verbatim, so a clone can plant `notes.txt -> ~/.ssh/id_rsa` or `-> ~/.aws/credentials`; any ordinary `grep` then returns the outside file's matching lines as tool content. Confirmed with a probe against `NewGrep(root)`: a symlink to a file in the temp dir's parent returned `notes.txt:1:SUPERSECRET_TOKEN=abc123`. `grep` is `ReadOnly() == true`, so it runs unapproved and unconfined in *every* mode including Plan, and in Auto the content is exfiltratable through the open network tools. This is worse than the pre-H1 read tools: the CHANGELOG records that for `read_file`/`open_file` the static symlink half "was never exploitable"; in `grep` it is, statically, with no race.
- **Fix:** open each walked file through `security.SafeOpen(root, rel)` (or walk with `os.OpenRoot(root)`), and add a grep-level regression test alongside `TestReadFile_Execute_RefusesEscapingSymlink`. While there, close the same check-then-use gap in the five tools the H1 sweep did not cover — `view_diff`, `present_document` (`present_document.go:95-108`), `diagnostics` (`diagnostics.go:107`/`:171`, which can take the already-read source bytes instead of a path), `list_dir` (`list_dir.go:66-71`) and `grep`'s single-file path.

### High — A forced (Tier-2) approval writes the allow-for-session cache `[Security]`

- **Where:** `internal/agent/dispatch.go:283-287` (write), `:264` (read)
- **What:** `approve` suppresses the cache *read* on `force` (`if !force && a.approved[cacheKey]`) but the `ApprovalAllowForSession` branch writes `a.approved[cacheKey] = true` unconditionally.
- **Why it matters:** `docs/design/confinement-execution-contract.md:439` states the opposite ("a forced gate … is never pre-allowable"), and `dispatch.go:255-257` repeats it. The model emits one call matching a Tier-2 rule — `sudo …` or `curl …|bash` — in Ask-Before or Allow-Edits; the human sees the forced prompt and presses `s` (the TUI offers allow-for-session on *every* prompt, `internal/tui/model.go:849`), intending to authorise that one dangerous call. `approved["terminal"]` is now set and **every later ordinary gate for that tool runs with no prompt for the rest of the Session** — the only approval boundary in those modes is gone. For an MCP tool the cached key is the *server* grain, so one forced prompt silently pre-clears every tool on that server. Confirmed with a probe: forced Tier-2 gate answered allow-for-session, then an ordinary sibling call — the Approver was consulted 1 time, not 2.
- **Fix:** gate the write on `force` too — `if !force { a.approved[cacheKey] = true }` — so a forced allow behaves as a plain `ApprovalAllow`. Pin it with the mirror of `TestMCPServerGrain_ForcedGateStillPromptsOnCachedServer`, which today only covers the read direction.

### High — Workspace context files are read with a bare `os.ReadFile` `[Security]`

- **Where:** `internal/agent/contextfiles.go:58`
- **What:** `loadContextFiles` does `os.ReadFile(filepath.Join(workspaceDir, name))`. The gate beside it (`validateContextFileNames`) validates only the configured *name* (`..`, absolute, drive-scoped); it cannot see what the name resolves to on disk, and `os.ReadFile` follows symlinks.
- **Why it matters:** a malicious repo ships `AGENTS.md -> ../../.ssh/id_rsa` (or `../../.apogee/config.yaml`, which holds the upstream API key). `context-files` defaults to `enable: true` / `names: [AGENTS.md]`, so the read happens the first time apogee starts in the clone, the contents are folded verbatim into the standing **system** message of every request, and the session notice shows only a name and a byte count. This defeats the fence ADR 0026 leans on ("a file above the workspace is outside the fence every other read in apogee respects") and diverges from the sibling reader in the same package — `readFileRef` (`loop.go:717`) deliberately goes through `security.SafeOpen`. Confirmed with a probe: an out-of-workspace file's contents came back in `contextFile.content`.
- **Fix:** read through `security.SafeOpen(a.cfg.WorkspaceDir, name)` + `io.ReadAll`, mapping `ErrPathEscape` onto the existing present-but-unreadable branch so the host reports the skip loudly instead of failing the session.

### High — `view_diff` reads unbounded and unfenced, then allocates a quadratic table `[Correctness + Security + Intent, cross-validated]`

- **Where:** `internal/tools/diff.go:69` (read), `:131-149` (LCS table), `:129-130` (the claim)
- **What:** `Execute` reads via `resolveInRoot` + `os.ReadFile` with no `maxFileReadBytes` check, never checks `args.NewContent` against `maxFileContentBytes`, and then allocates an `(n+1)×(m+1)` int LCS table. The in-code justification — "acceptable for the file sizes the read tools already bound (maxFileReadBytes)" — is false twice over: the bound is not applied here, and even at the bound the table is quadratic.
- **Why it matters:** measured, 6,000 × 6,000 lines is 282 MiB; 30,000 lines each side ≈ 7 GiB; a 10 MiB file of 250k lines ≈ 500 GiB. An erring model previewing a change to any large generated file (`package-lock.json`, a CSV, a long log) OOM-kills the whole TUI process on a laptop already sharing RAM with the local LLM, losing the in-flight Turn and any unsaved transcript — and `view_diff` is `ReadOnly() == true`, so it runs with no approval in every mode including Plan. The fill loop also has no ctx check, so Esc cannot interrupt it. The unfenced read additionally re-opens the check-then-use window that `readWorkspaceFileBounded` closed for `read_file`/`open_file`.
- **Fix:** read through `readWorkspaceFileBounded` (cap and pinned descriptor in one step), reject `newContent` over `maxFileContentBytes`, and refuse or degrade to a diffstat-only result when `len(oldLines)*len(newLines)` exceeds a fixed budget (e.g. 25e6).

### High — `git_branch switch` omits `--`, so a path-shaped name reverts the working tree `[Security + Correctness]`

- **Where:** `internal/tools/git.go:223` (`buildBranchArgs`), `:217-221` (create start-point)
- **What:** the `switch` action emits `git checkout <name>` with no `--` separator. `looksLikeOption` closes the option-flag class but not the ref-vs-pathspec class: when `name` is not a ref and *is* a tracked path, git restores those files from the index.
- **Why it matters:** confirmed with a probe — a repo with an uncommitted edit in `docs/notes.md`, then `git checkout docs` → "Updated 1 path from the index" and the edit is gone. A small model asking to switch to a branch that does not exist but whose name matches a directory or file (`docs`, `tests`, `main.go`) is a routine mistake. The tool then reports git's success text, so the model believes it switched branch and the user is never told work was discarded; the content was never staged or stashed, so there is no undo. It also defeats the mode ladder's intent: the human approving "switch to branch docs" is not approving a working-tree revert.
- **Fix:** terminate the ref position — `[]string{"checkout", args.Name, "--"}` — or use `git switch <name>`, which never interprets a pathspec. Apply the same `--` to the `create` start-point argument.

### High — A faulted sub-agent delegation is reported to the parent as success `[Correctness]`

- **Where:** `internal/agent/subagent.go:94` (`runSubAgent`), `internal/agent/dispatch.go:60` (`noteToolProductivity`)
- **What:** an abandoned child Exchange (`end(t, endAbandoned)`) returns `StatusExchangeComplete` — the same status a real completion returns. `runSubAgent` only special-cases `StatusCancelled`, so a faulted delegation returns `IsError: false` with either "(sub-agent completed with no final message)" or, worse, stale mid-task assistant text from an earlier child Turn presented as the delegation's result (`finalMessageText` scans for the last non-empty assistant message).
- **Why it matters:** the trigger is any Upstream fault while a sub-agent runs — a flaky or restarting local server, an overflow give-up in the child, a recovered hook panic. The parent model gets no error signal (the child's ErrorEvents reach only the human's EventSink), so it builds on a fabricated result; and `noteToolProductivity` books the failed delegation as a PRODUCTIVE write signal (`sub_agent` is not read-only ⇒ `noteWrite`), resetting self-regulation strikes and the Turn Budget on the strength of a failure.
- **Fix:** make the abandoned exit distinguishable at the seam — a fault marker on `StepResult`, or an `endAbandoned`-specific status — and have `runSubAgent` return `IsError: true` for it, so the parent model and self-regulation both see the truth.

### High — The syntax checker treats `//` as a comment in every language `[Correctness]`

- **Where:** `internal/mechanisms/syntaxcheck.go:139` (also `:136` for the correctly gated `#` case)
- **What:** on seeing `/` followed by `/`, `checkBrackets` breaks out of the line scan with no language gate. There is also no `/* */` handling at all, so a commented-out bracket corrupts the stack in C-family files.
- **Why it matters:** in Python `//` is floor division, so any bracketed expression containing it — `print(x // 2)`, `arr[i // 2]`, `range(n // 2)` — abandons the line before the closing bracket is seen and yields a false "unclosed parenthesis/bracket" on valid code. With `syntax` (or `autofix`) enabled, the mechanism fires `ActionRetry` telling the model its correct code is broken, burning up to `maxPostResponseRetries` (3) upstream calls per Turn and inviting it to mangle working code; `autofix` judges black's output against the same phantom errors, so repair can never "improve" it. That is a direct hit on the file's own contract ("reports only unambiguous breakage") and on the Bypass floor the project exists to protect. Ruby's `//` regex literals are the same defect.
- **Fix:** gate the `//` break to languages where `//` is a comment (js/ts/go/rust/java/c/cpp/csharp/swift/kotlin/php — not python/ruby), and either handle `/* */` or skip bracket accounting inside it. Then give the 307-line heuristic checker the negative table it lacks: valid snippets per language (Python docstrings and floor division, a JS string containing brackets and apostrophes, a Rust lifetime `'a`) asserting `checkSyntax(...).valid`, plus one broken snippet per error branch — today's only coverage is one broken Go file, one unclosed `(` in .js and one unclosed `[` in .py.

### High — Read-error sniffing over whole file bodies makes `read_loop` tell the model to overwrite existing files `[Correctness]`

- **Where:** `internal/mechanisms/historyhints.go:51` (`readErrorSignals`), `:72` (`resultIsReadError`), `internal/mechanisms/readloop.go:109`/`:150`
- **What:** the signals "not found", "no such file", "does not exist" and "error:" are substring-matched, lower-cased, against a committed read result's *entire* content — and a successful `read_file` result is the file body. Any source file containing `fmt.Errorf("error: %v")`, log output, or the phrase "does not exist" is therefore classified as a FAILED read.
- **Why it matters:** with `read_loop` enabled, `isGreenfieldContext` sees no successful read, so a session whose first action reads such a file stays "greenfield" and `detectReadLoopPaths` (threshold 1) fires: *"STOP. The workspace is empty. The file \"main.go\" does not exist because nothing has been created yet… Call write_file now. Do not call read_file again"* — after one successful read of an existing file, steering the model to overwrite it with a hallucinated reconstruction. Non-greenfield, two such reads fire "The file does not exist yet… use write_file to create it". Error-handling strings are ubiquitous in exactly the code a coding agent reads. The root cause is acknowledged at `:48-50`: the committed tool-result Message drops `ToolResult.IsError`, leaving only text sniffing.
- **Fix:** persist an error marker on the committed tool-result Message (or a `Message.Extra` flag) and read that; failing that, anchor the sniff to the result's first line or a prefix instead of a whole-body substring match.

### High — `StripHarmony` leaks `<|start|>role` into visible output `[Correctness, cross-validated]`

- **Where:** `internal/processing/harmony.go:92`
- **What:** the unterminated-tail path computes the visible lead as `tail[:strings.Index(tail, "<|channel|>")]`, which includes the `<|start|>role` prefix that `harmonyOpen` itself matches. The terminated-message loop gets this right by slicing at the regex match start (`loc[0]`, `:77-82`); only the tail path uses `strings.Index`.
- **Why it matters:** for `tail = "<|start|>assistant<|channel|>final<|message|>hello"` the result is `Visible = "<|start|>assistanthello"`. This is the normal shape mid-stream and for max-token-truncated replies from gpt-oss — the project's primary target model family — and it is exactly what the stripper exists to prevent ("a streaming analysis tail never leaks into Visible"). Reproduced against the real function. `harmony_test.go` covers `<|start|>` only with a *terminated* message (`:47`) and an unterminated tail only *without* the prefix (`:53`), so the combination is unpinned.
- **Fix:** use `harmonyOpen.FindStringSubmatchIndex(tail)` and take `tail[:loc[0]]` as the lead, and add the combined vector to `TestStripHarmony_FullChannelSet` (it fails today).

### High — The profile-load actuation path drives the engine off the Update goroutine and forks a second heartbeat chain `[Concurrency, cross-validated]`

- **Where:** `cmd/apogee/launcher.go:550` (`launcherWiring.load` → `w.move`) → `cmd/apogee/upstream.go:181` (`SwitchUpstream`); `internal/tui/actuation.go:366` (`foldActuationDone`); `internal/tui/model.go:1693` (`beatCmd`)
- **What:** two defects on one path. (1) `launcherWiring.load` runs on the actuation Cmd goroutine and ends, on the cross-server branch, in `sessionMover.move` → `agent.SwitchUpstream`, mutating the Agent's unlocked fields (`a.cfg`, `a.upstream`, `a.tokens`, `a.compactSat`) — while the Update goroutine can still drive `Agent.Rebind`, because the actuation latch gates commands and sends but *not* heartbeat-driven rebinds (`observeBinding` stashes only when `m.busy()`, which covers worker states, not `actuation.inFlight`). `rebind.go` states the contract: "the boundary the host crosses to call this IS the synchronization". (2) `foldActuationDone` ends the `verbLoad && !Moved` branch with `return m, m.beatCmd()` on the *current* generation without retiring the chain already running, unlike `foldServerSwitch`, which bumps `hb.gen` first.
- **Why it matters:** (1) a large-model profile load blocks for minutes; during that window any observed binding change — an Ollama-style server swapping models on demand, a second client reloading the shared server, an LM Studio GUI action — races the eventual switch with no happens-before edge, giving torn Config/provider-client state, requests to the wrong server, or a crash. A same-server load is safe, which is why it has not surfaced. (2) verified with a probe: after driving the same-server completion, a `heartbeatTickMsg{gen:1}` was re-armed *and* the pre-existing one was still accepted — two live chains on one generation, one more per load. That doubles `/v1/models` polling against the single-slot local server this product targets and halves the offline debounce (`offlineFailureThreshold` of 2 consecutive idle failures is now reached within one Interval), so the footer and `blockedUpstream`'s send refusal flip offline in ~10s where the debounce promises ~20s. `doc.go:246-248` states the opposite as an invariant.
- **Fix:** stop calling `SwitchUpstream` off the Update goroutine — have `launcherWiring.load` return the resolved move (endpoint/alias/key) in `tui.ProfileLoadResult` and let the actuation completion fold drive `sessionMover.move`; additionally gate `observeBinding` on `m.actuation.inFlight` exactly as it gates on `m.busy()`. Bump `m.hb.gen` before the immediate beat (or inside `beatCmd`, which makes it a pointer receiver, so callers must arm in a statement of their own per the `spinnerAnim.arm` convention), and pin chain uniqueness with a test.

### High — Staged interjections are drained into an Exchange that is being cancelled `[Concurrency]`

- **Where:** `internal/tui/worker.go:136` (`stepToBoundary`), `internal/tui/model.go:490` (`cancelledMsg` fold)
- **What:** `stepToBoundary` drains and commits the interjection mailbox at the top of every loop iteration without consulting `ctx`. `deliverInterjections` calls `eng.Interject`, which appends a user message inside the open Exchange; the next `eng.Step` returns `StatusCancelled`, and the fold calls `AbortExchange()`, which `DropRange`s everything from the Exchange boundary — the interjected message included. Meanwhile the `interjectedMsg` sent first has already run `foldInterjected`, removing those rows from `m.pendingInterjections` and writing them into the transcript as delivered.
- **Why it matters:** stage a remark with ⏎ while the model works, then press Esc during the following Turn: the remark stands in the scrollback as delivered, is gone from the queue ⏎ would resend, and is gone from the model's memory. A remark staged a moment later is correctly held by `noteHeldQueue`, so two identical user actions get opposite outcomes on invisible timing, and ADR 0025's "Esc stops everything, including what was waiting to go out" is only sometimes true.
- **Fix:** pass `ctx` into `deliverInterjections` and skip the drain when `ctx.Err() != nil`, leaving the rows in the mailbox (the queue of record). For a cancel landing after a successful drain, have the `cancelledMsg` fold re-stage the rows this Exchange delivered rather than leaving them only as transcript entries the conversation no longer contains.

### High — Mouse mapping and overlay rendering derive the frame's rows independently `[Intent + Correctness, cross-validated]`

- **Where:** `internal/tui/mouse.go:167-168` (`pointTranscriptRow`), `internal/tui/model.go:2195-2201` (View-time shrink), `:2306` (`contentLineAt`), `internal/tui/sessions.go:415` and `internal/tui/picker.go:606` (fixed `maxRows`), `internal/tui/model.go:2856-2869` (`popupBudget`)
- **What:** the frame's row budget is computed in three places that disagree. `layout()` sizes the viewport; `View` shrinks a *local copy* by the combined height of the approval/ask prompt, the `/sessions` browser, the picker, the autocomplete dropdown and the staged-interjection strip; and the mouse maps clicks against the unshrunk stored height. Separately, `popupBudget` — documented as existing "so the bordered pane never pushes the input box off-screen (D2)" — is consulted by the ask/approval prompts but not by `renderSessionBrowser` or `renderPicker`, and its own floor (`max(6, viewport.Height()-3)`) over-promises on short windows.
- **Why it matters:** screen rows `[drawnHeight, storedHeight)` are painted by the overlay but still map into the transcript. Verified on an 80×24 window: with the approval popup open, a left-click on the popup's top border armed a transcript selection anchored at content line 21, and a drag+release put 19 invisible characters on the system clipboard over OSC 52 with a "copied 19 chars" flash — hidden transcript text copied, and the gesture eaten on rows a user would naturally click to pick a session. `mouse.go`'s header claims the opposite twice ("the two never coexist", "what makes copy equal sight by construction rather than by care"). On the budget side, a probe with 8 stored sessions composed a 21-row frame on a 20-row terminal, and +5 / +9 rows on 16- and 12-row terminals, pushing the input box and footer off the alt screen — the exact outcome D2 forbids, plausible in a half-height tmux pane.
- **Fix:** give the Model a single "rows the transcript actually occupies this frame" derivation (the shrink `View` computes) and have `View`, `pointTranscriptRow` and `contentLineAt` all read it. Route the session browser and picker through `popupBudget`, and make its floor `max(0, …)` so the budget can shrink to nothing rather than over-promise. Reshaping where the shrink lives is a candidate for `/improve-codebase-architecture`.

### High — The Windows Low-integrity walk labels hard links, widening the fence outside the box `[Security]`

- **Where:** `internal/platform/winlabel/walk_windows.go:100` (reparse-point skip), `:127` (`SetSDDL`)
- **What:** the walk skips reparse points precisely because `SetNamedSecurityInfo` would follow the link and mutate a target outside the box — but hard links are not reparse points and are not detected. On NTFS every hard link shares one MFT record and therefore one security descriptor, so labelling the in-box name labels the underlying file Low wherever else it is linked.
- **Why it matters:** pnpm's `node_modules` is entirely hard links into `%LOCALAPPDATA%\pnpm\store`, and several package managers and build caches do the same. A Windows Auto session then gives the confined Low child — and every other Low-integrity process on the machine, e.g. browser sandbox children — write access to the user's global package store, which sits under `%USERPROFILE%`, outside `WorkspaceRoot ∪ WritablePaths`, and is exactly the location `windowsProtectedRoots` refuses to label when named directly. Poisoning a store package is persistent code execution outside the fence on the next build. The journal records only the in-workspace spelling, so `Residue` never names the affected file either.
- **Fix:** stat each descendant through `GetFileInformationByHandle` and put a file with `NumberOfLinks > 1` on the existing tolerated-descendant rung — skip it, label nothing, journal nothing — the same posture `descendantDecision` already takes for an unreadable prior.

## Medium Findings

### Medium — Session-record IDs from an untrusted file become filesystem paths `[Security]`

- **Where:** `internal/session/store.go:116` (Save), `:154` (Load), `:171` (Delete); `cmd/apogee/wire.go:855-865` (`resolveResumeArg`), `:716-726`
- **What:** `Store.Save` writes to `filepath.Join(s.dir, rec.Meta.ID+".json")` with no shape check on the id beyond non-empty. `resolveResumeArg` falls back to `store.LoadPath` on any readable file, and `newSessionHost` then adopts that record's `Meta.ID` as the active session identity, so every subsequent per-Turn autosave writes to the attacker-chosen path.
- **Why it matters:** a malicious repo ships a "session file" and induces `apogee --resume ./session.json`. A `Meta.ID` of `../../.claude/settings` makes autosaves overwrite `~/.claude/settings.json`; an ID equal to another stored session's id silently overwrites it; the browser's Delete on a content-declared id removes any `.json`-suffixed file the user can write. The embedded `transcript` RawMessage is written verbatim, so the content is partially attacker-controlled. A planted record whose `Meta.Workspace` names another repo also hijacks `--continue` for it.
- **Fix:** validate `Meta.ID` at `decodeRecord`/`Save`/`Delete` — accept only the minted shape (`20060102T150405Z-8hex`), or at minimum reject ids where `id != filepath.Base(id)` — and re-mint the id when adopting a record loaded from an explicit path.

### Medium — The document server re-opens the granted path per request with no fence `[Security]`

- **Where:** `internal/present/server.go:236` (`handle`), `:115` (the one-time `os.Stat`), `:196` (listener), `:201` (timeouts)
- **What:** `Serve` validates the document once and stores an absolute path; `handle` then does a bare `os.Open(file)` on every request, outside `os.Root`/`security.SafeOpen` and with no re-check that the path is still inside the workspace. The `http.Server` sets only `ReadHeaderTimeout` — with no `ReadTimeout`, Go's `IdleTimeout` falls back to 0 — on a listener bound to every interface.
- **Why it matters:** anything that replaces the granted path with a symlink after the grant — the model running `ln -s ~/.apogee/config.yaml report.html` inside the workspace (a write the fence permits, since it bounds the write *location*, not the link target), or a `git checkout` of a branch carrying that name — makes the server hand out the target instead, at a URL whose token the model already has, from off the box. That is the API key or `~/.ssh/*` served over the network. Separately, an unauthenticated peer on the network — the remote/devbox deployment rung 2 exists for — can pin unlimited keep-alive connections open (a wrong token still gets a served 404), exhausting file descriptors and breaking the agent's own file and network operations.
- **Fix:** store the grant as `(root, workspace-relative name)` and re-open through `security.SafeOpen(root, name)` per request (or keep the `*os.File` from `Serve` and re-`fstat` that descriptor). Set `IdleTimeout` and `WriteTimeout`, and cap concurrent connections with a `netutil.LimitListener`-style wrapper.

### Medium — With an unknown context window every growth bound is inert and the session wedges `[Correctness + Concurrency]`

- **Where:** `internal/agent/compact.go:234` (`compactTranscriptChars`), `:236-238`, `:150`; `internal/agent/loop.go:662`; `internal/agent/dispatch.go:459`
- **What:** when neither discovery nor `context-window:` reports a window, four bounds fail at once: the predictive guard never fires (`room <= 0`), auto-compaction never triggers (zero History allocation), the structural tool-result clamp is disabled, and `compactTranscriptChars` returns 0 — so the emergency fold's own summary call renders the WHOLE conversation.
- **Why it matters:** once the history alone exceeds the server's real window, that summary request overflows just as surely as the request it was meant to rescue, so `emergencyFold` faults every time: each user message costs two failed round-trips, emits an ErrorEvent, and abandons the Exchange — permanently, until `/clear` discards the history (`/compact` uses the same unbounded render and fails identically). The trigger is an OpenAI-compatible server whose `/v1/models` omits the context length plus a long session, i.e. exactly the configuration whose own comment calls the reactive path "the only protection".
- **Fix:** when the window is unknown, bound the summarizer transcript by a conservative default (a few thousand tokens via the calibrated ratio) instead of 0 so the fold can actually shed history, and have the give-up ErrorEvent name the remedy ("set `context-window:` in config") rather than leaving the user with a silently wedged session.

### Medium — The Library store rewrites itself in place, so a torn write discards everything `[Correctness]`

- **Where:** `internal/library/store.go:285` (`persist`), `:110-115` (`Load`)
- **What:** `persist` rewrites the whole store with a plain `os.WriteFile` (truncate-in-place) and runs on *every* `Record`/`RecordSuccess` during live sessions. A crash or power loss mid-write leaves a truncated `library.json`, and the next `Load` soft-degrades to an EMPTY store.
- **Why it matters:** the soft-degrade posture is documented for an externally corrupted store, but this makes total loss of the cross-session learning record reachable from normal use — not just the interrupted observation, everything. Every other record writer in the tree (session records, config splices) already uses temp+rename.
- **Fix:** write a temp file in the same directory and rename over the store — atomic on every target OS, and it removes the only self-inflicted corruption path.

## Recommended Action Order

1. **Serialize session-record writes** (the Critical). It is the only data-loss defect that fires under default configuration, and fixing it at the `session.Store` layer also settles the adjacent boundary bugs (a coalesced save dispatched across `/clear` or a `/sessions` resume can file the outgoing conversation under the new session's id or overwrite the record just resumed). Deciding *which* layer owns record-write serialization — the store or the TUI single-flight — is a candidate for `/improve-codebase-architecture`.
2. **The four local security fixes that already have probes written**: the forced-gate cache write (one `if`), the context-file `SafeOpen`, the `grep` walk fence, and `git checkout … --`. Each is a few lines with a ready-made regression test, and each closes an exploitable path for an attacker the threat model names.
3. **Bound `view_diff`.** One function, prevents an OOM kill of the whole process from a routine model action.
4. **Mask the landlock access set by probed ABI** (and add `REFER`). This is a prerequisite for any honest Auto-on-Linux claim and for the owner-run enforcement proofs still pending in the CHANGELOG; it is unverifiable on the dev host, so it needs a table test plus one run on a 5.15 or 6.1 box.
5. **Move escape-stripping to the transcript seam.** One change closes five-plus producers at once and stops the enumeration from rotting again; extend the pinned regression test to the newly covered paths.
6. **Discuss before fixing: `autofix`'s external formatter.** Routing it through the tools execution seam versus dropping the prettier rungs is a design call about what a silent repair step is allowed to do; both the security hole and the `WaitDelay` deadlock live at the same call site and should be settled together.
7. **The two composing-state fixes in the engine**: sub-agent effective-mode (plus the ADR 0013 wording correction) and the Plan tool menu keying on the same fact as the resolution ladder.
8. **`MergeDangerousRules`.** Latent today, but it must land *before* dangerous-rule config surfacing is wired, and the fix includes correcting the two tests that currently encode the loophole.
9. **The TUI/launcher concurrency pair** — hand the profile-load move back to the Update goroutine and retire the heartbeat chain — then the interjection ctx check. These share the actuation path and are best done in one pass.
10. **The mechanism heuristics** (`//` in every language, whole-body error sniffing). Both mechanisms are default-off, which lowers urgency, but when enabled they actively mis-steer the model on everyday input, which is the one outcome the Bypass floor exists to prevent.
11. **The remaining Mediums**, cheapest first: the Library store's temp+rename (two lines), the `--resume` id validation, the unknown-window summarizer bound, the doc server's per-request re-open.

## What Looked Good

The deliberate security machinery is strong and unusually well reasoned where it was designed as a seam rather than a habit: the network funnel (single `do` path, pre-flight plus dial-time SSRF floor with NAT64 decoding, redirect refusal, URL-scrubbed error text), `security.SafeOpen`'s `os.Root`-pinned TOCTOU-safe I/O, the unfakeable `workspaceScopedWriter` / `urlFilteredNetworker` markers, the git env allowlist, the subprocess process-group teardown, and the fact that keys never reach a flag, a report, or a picker row. The agent's Resolution/dispatch split is genuinely well built — `resolve()` is pure and table-tested, the guard floor runs before the ladder, and the Turn lifecycle, cancel/rollback bookkeeping and one-fold-per-Turn overflow recovery are internally consistent and closely test-pinned. Concurrency discipline is real and mostly enforced: the single-goroutine Agent contract with two documented anytime-safe exceptions behind their own RWMutexes, generation guards on both tick chains, cancel-safe rendezvous with buffered replies, `programRef`'s atomic hand-off, and correct mutex discipline in `provider.Client`, `present.DocServer`, `library.Store` and `skills.Provider`. And the test suite is a genuine asset — the policy half of every OS confinement backend is table-tested off its own OS, the Windows label lifecycle carries 20+ native tests including crash recovery and sibling interleavings, the oracle-parity parser suites and adversarial escape/traversal/token tests are exemplary, and the always-on `-race` gate is backed by real multi-goroutine tests rather than assertions in comments. None of that should be disturbed while fixing the above.
