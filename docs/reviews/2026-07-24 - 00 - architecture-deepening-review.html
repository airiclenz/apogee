Apogee — architecture depth

24 July 2026 · ~34k LOC across 18 internal/ packages · five subsystems explored organically

What this looks for

Deep = a lot of behaviour behind a small interface. Shallow = the interface is nearly as wide as the implementation. The review hunts shallow modules, leaky seams, and concepts with no structural home — and proposes deepening them for locality and leverage.

Legend

  • module
  • deep module
  • seam
  • leakage across a seam
The good news first. The spine is already deep and should not be touched: resolve() (the whole Resolution verdict behind one pure function), runSubprocess (every subprocess tool funnels Confinement through one point), the Confiner seam (three radically different OS backends behind two methods), the Mechanism dispatch / self-regulation core, the provider.Responder seam, and fingerprint identity. The candidates below are the friction around that spine — several of them are "make X follow the pattern the codebase already trusts."

Give the Turn a lifecycle owner

Strong in-process

internal/agent/loop.go · compact.go · selfreg.go · state.go

Before — one concept, six homes

step() loop.go · the 1172-line file

abandonTurn

↯ each end-helper touches a different subset of {tracker, turnIndex, rollback, deferred, inExchange}; the rules relating them live in 15-line defensive comments, not a type.

↯ the overflow re-derive ritual (restoreDeferred → emergencyFold → rebuild req/rollback/deferred) is copy-pasted; buildRequest is reconstructed 7× in loop.go. exchangeStart is written in 5 places.

After — one deep turn module

turn

owns {tracker, turnIndex, rollback,
deferred, inExchange, exchangeStart}

complete
abandon
cancel

exit table · one fold() → fresh req/rollback/deferred

step() reads as a loop again: t.begin() … t.complete/abandon/cancel. The three exits become rows in one table; the prose invariants become code.

Problem. How a Turn begins, recovers from overflow, and ends is the loop's central concept — and it has no module. Correctness depends on non-local prose spread over six functions, plus a re-derive ritual pasted three times.

Solution. A small deep turn lifecycle module that owns the state tuple, exposes the three exits as a table, and folds overflow-recovery into one fold() that returns the fresh working values instead of leaking its post-conditions onto step().

  • ✔ locality: one place owns "how a Turn ends"
  • ✔ leverage: step() is a loop, not a ledger
  • ✔ deletes the 3× overflow ritual + 5-way exchangeStart writes
  • ✔ interface shrinks; implementation absorbs the prose
  • ✔ measured against resolve() — the exemplar deep module already in this package
No ADR conflict — this is engine-internal shape. The test friction it removes is real: today self-regulation is only assertable by reaching through the Agent into a.tracker / a.conv / a.exchangeStart (163 a.conv reach-ins across the tests).

Hand the view structured tool results

Strong seam

internal/tui/toolpresent.go · internal/tools/{read_file,write_file,list_dir,grep}.go · internal/domain/tools.go

Before — the view scavenges prose by regex

internal/tools/read_file.go
emits "…showing lines 1-154]"
↓   free-text string, for the model
internal/tui/toolpresent.go
reReadRange = /showing lines (\d+)-(\d+)/
reWriteBytes · reListEntries · reGrepMatches
degrades to first-line if format drifts

↯ a stringly-typed cross-package contract with no type. The TUI doesn't even import internal/tools — it re-derives what a tool did from the prose the model reads.

After — a typed summary crosses the seam

internal/tools/read_file.go
returns ToolResult{Summary: ReadSpan{1,154}}
↓   typed field on ToolResult
internal/tui/toolpresent.go
reads fields; keeps only labels/verbs

Result semantics live once, in the tool. The view stops re-parsing engine output — ADR 0011's thin-renderer honoured by construction.

Problem. A 24-entry registry in the view reconstructs each tool's outcome by regex-matching the result string meant for the model. A format tweak in internal/tools silently degrades the card to a verbatim first line, with no compiler nudge.

Solution. Tools emit a small structured summary alongside Content (a typed field on ToolResult); the view reads data. The presentation labels and verbs legitimately stay in the TUI.

  • ✔ locality: result semantics live once, in the tool
  • ✔ leverage: one typed seam replaces N regexes
  • ✔ deepens internal/tools; thins the view's leakiest file
  • ✔ the same summary feeds a future headless / bench host
Additive to the public ToolResult (domain) — a minor bump under ADR 0010 stability, back-compatible with ADR 0002's open tool extension point (the summary is optional; a third-party tool that omits it falls back to today's prose).

Collapse the 21× Mechanism registration ritual

Strong in-process

internal/mechanisms/*.go · catalogue.go · internal/domain/mechanism.go · internal/agent/loop.go (buildEnabledMechanisms)

Mass diagram — interface surface vs implementation, per trivial Mechanism

interface
7 parts
impl

Before — shallow: the ritual (ID const · 2-map init() · struct · constructor · descriptor var · Descriptor() · Ordering()) rivals a 10-line behaviour

Register()
impl

After — deep: one Register(descriptor, ordering, constructor); the file is its hook method + one descriptor literal

Problem. Every Mechanism repeats a 7-part ritual of near-constant size regardless of behaviour — 19 init()s, ~21 Descriptor() + Ordering() methods, two parallel maps (catalogue + descriptors) hand-synced, an ID re-declared as a literal in a second package, and a dependency-bearing Mechanism special-cased inside buildEnabledMechanisms. For the ~8 trivial Mechanisms the ritual is the module.

Solution. One Register(descriptor, ordering, constructor) that writes a single {constructor, descriptor, ordering} table, derives the ID from descriptor.ID, and synthesizes the two methods. Let a catalogue row declare its dependencies so the engine loops uniformly.

  • ✔ locality: a Mechanism file is only its behaviour
  • ✔ leverage: one registration interface for 21 Mechanisms
  • ✔ deletes 2 methods + a var + an init line × 21
  • ✔ kills the two-map drift + the cross-package ID leak
Preserves ADR 0003 — the constraint-declared registry's ordering / stacking semantics are unchanged; only the authoring seam deepens. The deep dispatch and self-regulation core is left exactly as it is.

Smaller deepenings — real, but lower leverage

Each passes the deletion test but concentrates less than the seven above. Grouped so they don't crowd the headline set.

Give the self-regulator a read model Speculative

selfreg.go exposes no accessors, so 22 tests poke strikes/suppressed/budgetTripped directly. A small observed-state accessor moves the assertions behind the seam — same caller interface, far less test reach-through.

Let the session store own the whole snapshot lifecycle Speculative

internal/session (72 LOC) is write-only Save; the read path lives in domain.DecodeSession + a caller's ReadFile. Give it Save/List/Load so one module owns the concept — deep, following the probe observe-then-render pattern.

One workspaceWriteTarget helper

The marker body (decodeArgs → resolveTargetUnbounded) is copied across write_file / file_edit / find_replace. A single path-arg helper collapses the four identical bodies.

Route read_file through SafeStat/SafeReadFile

The TOCTOU-safe os.Root-pinned primitive exists and is documented for read_file, but read_file still does resolveInRoot → os.Stat → os.ReadFile — the check/use gap the primitive was written to close.

A POSIX Confine argv-wrap helper

landlock and seatbelt share a verbatim cmd-rewrite skeleton (guard args · prepend launcher · Setpgid). wrapArgvUnderLauncher + setConfinedPgid absorbs both; the genuinely-varying ruleset/profile cores stay separate.

Break up loop.go (1172 LOC)

Two self-contained deep modules are trapped in the god-file: the construction cluster (newAgent/buildEnabledMechanisms/resolveTools) and the domain→wire translation cluster (toProviderRequest…). Extracting them shrinks the surface a loop reader must scan. Complements candidate 01.

Reconsider where Request.InjectContext lives Speculative · reopens an ADR line

It encodes chat-template role-safety policy (where an injected message lands) inside a domain data type. The engine / context layer already owns role-alternation. Moving it up would sharpen ADR 0010's "domain holds only logic intrinsic to its types" line — but that line is deliberate and the current placement is defensible (the working value has to carry the boundary across hook mutations). Flagged, not recommended, without a grill.

01 · Give the Turn a lifecycle owner

The Turn is Apogee's central loop concept, and it is the one with no module — its begin / recover / end rules live as defensive prose across six functions, its overflow-recovery ritual is pasted three times, and it is only testable by reaching through the Agent into private state. Every other candidate improves a periphery; this one deepens the heart of the engine, and the package already contains its yardstick — resolve() — so the target shape is proven in the same package.

Highest leverage, highest locality gain, no ADR conflict. Candidates 02 (url-safety choke point) and 04 (Mechanism registration) are the strongest follow-ons: both are "make X follow the deep pattern the codebase already trusts," and both are lower-risk than 01.
