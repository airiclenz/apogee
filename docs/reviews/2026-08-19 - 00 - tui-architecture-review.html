Verdict up front: the package's deep modules are genuinely deep — popup.go, the tool registry, the event fold, the width authority all pass the deletion test decisively. The friction is concentrated in three shapes: state machinery written N times where one module should exist, facts re-derived that a composer already computed, and clusters still living inside model.go / oversized files after ADR 0043's split stopped early. Nothing below loses functionality; most candidates delete or relocate code.

Strong in-process

After — one deep module, panes supply content

picker: rows·accept·hint sessions: rows·accept·hint settings: rows·accept·hint …

listSurface (value type)

selection · clamp · ↑↓ wrap rule (one answer) · filter buffer · window · esc · budget→render call

Interface: rows in, key verdict out. Directly unit-testable — today “↓ at the bottom of a filtered list” needs a whole Model (13,400 test lines pay that tax).

Problem. popup.go deepened the painting of all eight panes; nothing deepened the state — so selection, clamp, wrap-around, and filter knowledge is written 6–8 times with small silent divergences.

Solution. One value-typed list-surface module every pane embeds; each pane keeps only its rows, its accept action, and its hint line.

  • locality: arrow/filter bugs in one module
  • leverage: one interface, ~35 call sites
  • delete ~200–300 duplicated lines
  • tests hit one interface, not Model
  • next pane costs rows + accept only

Fits ADR 0043 (one new file, package stays flat) and ADR 0011 (plain value, no lock). Prerequisite: the three raw-string filter/rename buffers route through lineEditor-class fields first — the package currently answers “what does backspace do” in five places and draws a caret three ways.
