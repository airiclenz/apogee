One outright defect surfaced in passing (this review designs structure; it does not audit): the post-tool-result acted probe snapshots before := *result (internal/agent/hookrun.go:256) and compares *result != before (hookrun.go:260), which panics on the uncomparable domain.OpenedFile summary — deterministically, exactly when the hook did not act: Go's struct compare short-circuits at the first differing field, so a successful open_file result (whose LocatedOn []int makes the type uncomparable) reaches the summary only when no earlier ToolResult field changed. error_enrichment by design never acts on a non-error result, so a successful open_file with it enabled (it ships in the gemma-4 Validated set, internal/validated/shipped.json) panics deterministically. The panic unwinds Agent.Step through the tea.Cmd closure with no recover on the path; Bubble Tea v2.0.7's default catchPanics recovers it, restores the terminal, prints the stack, and Program.Run returns ErrProgramPanic — the entire TUI process exits mid-Exchange (in-flight Exchange lost; per-Turn saves up to the previous Turn survive). Not a degraded-hook continuation, not a terminal-corrupting raw crash. 1 · One Mechanism runner, one acted probe

Strong in-process

Each duplicated for the experimental twin ⇒ 10 loops, 10 type assertions, 3 error conventions, 3 probe flavours — and the twins are not faithful copies: the post-tool-result compare exists only in the catalogued loop (snapshot :256, compare :260); its experimental twin (:264–273) never compares, booking the fire unconditionally. After — one deep dispatch over one probe

recover boundary — around everything

acted probe = value.Revision()

All five working values answer "did a Mechanism change me" the same way; the runner is one generic loop parameterised by Hook point + invoke closure.

Problem. The Mechanism runner's interface includes the private mutation-detection strategy of five different domain types — so the runner is five hand-written copies of one skeleton, and the copy that lacks a revision counter crashes on an uncomparable Tool summary.

Solution. Give all five working values one Revision() and collapse the ten loops into a single dispatch module that owns the walk, the skip gate, the recover boundary, and the acted probe.

  • locality: R4 lives once
  • one probe, five Hook points
  • the interface becomes the test surface: hookrun gets its own table test
  • a fourth working value comes for free
  • deletes the TUI-exiting compare

Self-regulation (Adaptive Suppression, Turn Budget) counts on the acted-fire signal — this seam is the operational half of the hard constraint, and today it has no interface of its own. Absorbs the domain/hooks.go observation that the working-value pattern (revision + view + mutation API) is implemented three times without being named.

It sits at the loop's core: the acted-fire signal feeds Effectiveness tracking, Adaptive Suppression, and the Turn Budget — the operational half of the hard constraint — and today that signal is five hand-rolled probes, one of which panics and exits the entire TUI (confirmed by live repro 2026-08-01).
