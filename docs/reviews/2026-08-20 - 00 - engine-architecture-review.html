1 — One Mechanism runner behind one hook-fire seam

Strong in-process

internal/agent/hookrun.go (355) · internal/domain/mechanism.go (359) · internal/domain/tools.go:174-194

Before — five hand-written runners

pre-request runner · own acted probe (Revision)
post-response runner · own acted probe (Revision)
history-rewrite runner · no LoopView at all
pre-tool-exec runner · bespoke callSnapshot/callChanged
post-tool-result runner · bespoke DeepEqual probe (panicked in prod, hotfixed)

× 2 — each repeated for the experimental-hook list. 218 of 355 lines are the same seven steps.

After — one deep runner

runHooks — ordered → gate → bracket → fire → book

one Revision() bracket · one recover boundary · one booking path

pre-req
post-resp
hist-rw
pre-tool
post-tool

five thin adapters; tool stages gain revision-bearing working values

Problem. Every hook point re-implements the fire protocol, and the two tool-stage hooks lack a Revision() counter — so their hand-rolled acted probes diverged and one shipped a production panic (commit 558cd073). The hotfix comment at hookrun.go:315-318 promises a "Mechanism-runner consolidation" that exists in no plan, no ADR, no ISSUES entry.

Solution. Give ToolCall/ToolResult revision-bearing edit values like the three the other hooks already have, then collapse the ten loops into one generic runner with five adapters.

  • locality: acted-probe bugs die once
  • leverage: one runner, five hook points
  • the DeepEqual bug class disappears
  • tests: 25-cell table replaces 2-of-5 coverage
  • honours the orphaned HOTFIX promise
The 2026-07-24 review marked this module "leave alone" — that verdict pre-dates the panic and the orphaned hotfix by five weeks. ADR 0003 fixes the registry and ordering, not the runner count; no conflict.

Companion (do together): Ordered(at) re-runs a full topological sort on every dispatch (~23 sorts per Turn with a full catalogue); the registry is declared read-only once the engine has it, so freeze the order at construction.

The evidence

Argument order flips between ResolveInRoot(input, root) and SafeWriteFile(root, input, …); SafeCopyFileFrom takes five consecutive strings, four of them paths — the compiler can catch nothing. The permit rides as a trailing string through four signatures. capturePreImage ×4 sites, commit ×8, writeEscapeTarget ×4, disclosure note ×7 — "a refused write journals nothing" is eight promises, not one.

After — one fence, one mutation protocol

security.Fence{root, permit}

Read · Open · Stat · Write · Remove · Rename · CopyFrom · Mutate(spec, fn)

Mutate owns: permit check → disclosure → pre-image → primitive → commit-if-landed

One path string per call; the permit is a property of the fence you were handed; the tools alias layer is deleted; the three hand-woven verbs call the funnel like the four writers already do.

Problem. The fence's interface is nearly as wide as its implementation — seven signatures in three inconsistent argument orders, a pass-through alias layer that exists only to re-order them, and the undo/permit/disclosure protocol re-derived at three mutation sites outside the funnel.

Solution. A fenced-root value with per-verb methods and one Mutate that owns the whole write protocol; tools keep only their own wording.

  • interface shrinks; permit stops travelling positionally
  • locality: undo-journal invariant lives once
  • tests: permit table at the fence, not per tool
  • ~60 lines of protocol deleted from three tools
ADR 0049's "permit is asked first, on the resolved path" and ADR 0051's journal-at-the-funnel are both easier to state on a Fence — no conflict.

4 — One Binding for "the resolved binding to an Upstream"

Strong in-process

internal/agent/rebind.go (RebindSpec, UpstreamSpec) · delegationtarget.go (DelegationTarget) · subagent.go · cmd/apogee/headless.go:342-431

Before — three sibling structs, three zero-value dialects

RebindSpec

MaxOutputTokens *int — nil = keep

UpstreamSpec

MaxOutputTokens int — 0 = clear

DelegationTarget

ContextWindow int — 0 = keep parent's

Same three numbers; a caller must know which sibling it holds to know what zero means. Each has exactly one production construction site — three hypothetical seams.

After — one value, one optional convention, one apply

Binding

endpoint · key · model · window · output cap · reserve share · profile

apply(*Config) — one documented optionality rule

Rebind, SwitchUpstream and the routed spawn each become validate → apply → commit. headless.go stops unpacking a RebindSpec field-by-field into a Config — the two were always two shapes of one resolution.

Problem. The engine spells "what this session is bound to" three ways with contradictory zero-value contracts, applied by hand at three sites — a seam leak a maintainer must simply know.

Solution. One Binding value with a single apply method feeds Rebind, SwitchUpstream, routed spawns and Config construction.

  • locality: window/cap/reserve rules in one table
  • the inconsistency itself becomes a visible test row
  • six scattered inheritance tests collapse to one
ADR 0024/0028/0045 define policies, not struct counts; ADR 0031 holds — the Binding is still computed whole by the Driver.

6 — The live session setting becomes a declared policy, not prose

Strong in-process

internal/agent/agent.go (39 field lines, 8 mutexes) · subagent.go:178-337 · cmd/apogee/wire_engine.go (498)

Before — interface as wide as the implementation

7 single-scalar mutexes
28 setter/getter bodies
22-line prose taxonomy

Adding one setting = six files, each with an unchecked judgement call: inherit-live vs isolate in newChildAgent, remember vs no-op vs refuse in lateEngine, plus TUI method + root alias. Measured ripple: 5–7 files per real setting.

After — short interface, tall implementation

liveField[T] + declared
inherit / bind policies

newChildAgent becomes a loop over declared policies; lateEngine's 15 pure forwarders and hand-ordered Bind replay become a table replayed in insertion order. A setting that forgets its policy fails to compile.

Problem. The three call classes (idle-only / between-Steps / anytime-safe) and the Sub-agent inherit-vs-isolate rules exist only as comments — ~120 lines of prose over ~40 lines of assignment in subagent.go — and lateEngine restates the remember/no-op/refuse policy 29 times, with a hand-ordered replay a forgotten setter silently drops.

Solution. A small settings module holding value + lock + declared inheritance and bind policies; the child spawn and the pre-bind replay become loops over the declaration.

  • locality: the class taxonomy becomes a type
  • tests: one inheritance table replaces 1,300+ lines across 5 files
  • "every remembered edit reaches the Agent" — one exhaustive loop
ADR 0013 fixes what a child inherits, not how it's threaded; ADR 0037 is served better by declared policy. Same medicine as ADR 0054's Options groups, one layer down.

A package-internal generic execute[A] keeps ADR 0002's public Tool interface untouched and unlocks the roster-wide invariant test (bad arg ⇒ IsError; cancelled ctx ⇒ Go error) that today holds for 4 of 25 tools.

The presentation ladder moves into internal/present Worth exploring

The 43-line climb policy — including the security-relevant rung-1/rung-2 extension crossing on .pdf — lives in the TUI, above the 3,297 lines it decides between. A present.Ladder keeps the host in charge (ADR 0019) and makes a headless rung-0 Presenter a struct literal.

One idle-only guard Worth exploring

Nine call sites hand-write the in-Exchange gate with four different error spellings. An atIdle(reason) guard gives the call class one implementation and makes the door list enumerable in one table test. Implements ADR 0007/0037 rather than conflicting.

domain/hooks.go splits; the seam comment becomes true Worth exploring

985 lines, four primary types — and a comment claiming the engine-seam surface is "not re-exported", while the root's type aliases export all 14 Request and 19 Conversation methods. Split by concern (ADR 0043's own rule) and decide the seam's public status honestly.

One subprocess spawner for tools and Mechanisms Worth exploring

runSubprocess is the deep funnel (Confinement handoff, env scrub, teardown); autofix's formatter reimplements the handoff and skips the rest — inheriting APOGEE_API_KEY and reaping nothing. Route it through the funnel; three protections gained for free.

processing sheds its double switch Worth exploring

Model profile → parser goes through two switches over two spellings of one enum; 15 exported symbols have zero callers outside the package, and the "emit and parse can't drift" guarantee holds only because both sides ignore the same config field. Fold the switch into ParserFor, unexport the rest, and the emit/parse pairing becomes a statable invariant.

Retire a Confiner in one place Worth exploring

Both Drivers do the same anonymous-interface Close dance; a third that forgets it leaves mandatory labels on the user's disk. One platform.RetireConfiner honours the recorded decision (no teardown method on the public interface, ADR 0010) while deleting the duplication it created.

Speculative, recorded but not recommended without a grill: regrouping domain.Config's 34 fields (a public-API break under ADR 0010's stability rule); a title.Namer folding the naming call behind the sanitiser; re-homing model identity across five packages (the 2026-07-24 review examined and refuted this — the one new fact, the mirrored ProbeBatteryVersion constant, is not enough to reopen it).

Top recommendation

Candidate 1 — One Mechanism runner behind one hook-fire seam.

It is the only candidate with a shipped panic in its history and a load-bearing HOTFIX comment promising exactly this consolidation — a promise no plan owns. The scope is bounded (one file plus two domain working values), it deepens the seam every Mechanism crosses, and it unlocks the 25-cell acted-probe table the self-regulation story rests on. Second in line: candidate 2 — the config copy chain is the largest day-to-day friction (12+ edit sites per key) and candidates 8 and 9 fold naturally into its wake.
