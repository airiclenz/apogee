# Tools umbrella fold consistency — implementation plan

**Goal:** The `✦ Tools (N calls)` umbrella folds and toggles by its SIZE alone — the same whether the Turn is running, cancelled or finished, in the main transcript or a sub-agent's run view, live or resumed — and EVERY umbrella wears `▶`/`▼` and folds to its header: large ones under the shared `ui.tools-open`, small ones on their own session-only flag. Fixes the regression from `e3f098e5`/`fec8db32` (plan 2026-09-17 - 01): `umbrellaIsLarge` gated on `transcript.busy` and every member `done`, so an umbrella inside a sub-agent's run view opened while the parent Turn runs — the one place a >5-row umbrella ordinarily appears — never folded and carried no toggle.

**Status:** unexecuted
**Sized for:** ~200k-context host

**Ratified design calls (user, 2026-09-18):**
- **Large rule:** type rows > `ui.tools-fold-over` (and threshold > 0), full stop — no Turn-busy gate, no members-done gate. Same answer at every depth, in every view, live or replayed.
- **Every umbrella foldable:** every `✦ Tools` header wears `▶`/`▼`; a click or ⏎ on it folds the umbrella to its header line or opens it. The shipped "small header click closes every open child" rule is superseded (child state survives beneath a fold and is there again on reopen).
- **Fold scope:** a LARGE umbrella follows the one shared `ui.tools-open` (toggle flips them all, written back — unchanged). A SMALL umbrella folds on its own head-entry flag, in-session only, never written to config, never serialized; it starts open every session. A small umbrella that grows large follows the shared preference from then on; its own flag is ignored while large.
- **Threshold unit:** type rows (unchanged).
- **Live header:** a folded umbrella with a call still running paints its header with the blinking `✦` exactly as an open live umbrella does, `(N calls)` counting; nothing else on the line.
