# The three P2 fixes: reserved recipe inputs, one seed check, advice rows

**Goal:** A recipe input can never shadow a placeholder a workflow fills, and the reserved names have one home. Drivers check a seeded Generation with the engine's own seed check, so a list construction would refuse never reaches the Runner. The `/advice` pane paints no empty row after a Detail's trailing newline.
**Date:** 2026-10-29
**Status:** unexecuted
**sized for:** ~200k-context host
**base:** 65ebeaff
**Sources:**
- Issues: `recipe-input-shadows-placeholder`, `driver-lane-precheck-gap`, `advice-pane-trailing-row` (`capcom show <id>`)
- `docs/plans/archived/2026-10-27 - 00 - session-briefing-and-construction-seed-plan.md` — the construction seed, items 3 and 6 NOTES
- ADR 0010 (cmd/apogee reaches the engine through the root facade) · ADR 0031
- `docs/manual/workflows.md` §Inputs

**Ratified design calls:**
- **Reserved inputs** (owner, 2026-10-29): every placeholder a workflow fills is a reserved input name — `apogee`, `workflow_dir`, `part_bytes`, `SKILL_DIR`, `item`, `out`, `claim`, `output`, `manifest`. `ValidateInputs` refuses each by name; the silent `item`/`out` binding skip goes away.
- **Refusal wording** (writer): the `apogee` refusal stays byte-identical; every other reserved name is refused in the same form, `input name %q is reserved: <what its placeholder names>; rename the input`. Names compare case-sensitively, as placeholders do.
- **Seed check** (writer): one exported `agent.ValidateSeed(gen domain.Generation, workspaceDir string) error` runs `validateGeneration` and the sync-lane scope check and returns a `*SeedRefusedError`; construction calls it, the root facade forwards it, and both Drivers run it before `Runner.Replace`.
- **Advice rows** (writer): trailing newlines are trimmed in the pane only; `bookedDetail` keeps them (apogee-sim hashes Detail byte for byte).

**Standing requirements:**
- skills: coding-standards
- Test-run rules for this machine (pass them to every sub-agent): run only `GOMEMLIMIT=2GiB go test -count=1 -run '<pattern>' ./<one pkg>/`. Never `-race` or `-cover` over a whole package. Never two test runs at once.
- Every user- and model-facing string not named in an item stays byte-identical.

**Out of scope:**
- The thinking pane's untrimmed split (`wrapThinkingText`).
- `transcript.addReaction`'s debug-view Detail.
- `SetReactions`' own validation path (it keeps `validateGeneration` + scope with plain errors).

**Regression check (2026-10-29, 65ebeaff):**
- 1: guard folded (reserved-ahead-of-use wording + CHANGELOG load note; §Inputs-scoped doc check and placeholder-const grep; exact `apogee` message assert added; parse-test row moved in from item 2).
- 2: recast (every recipe's inputs checked by `workflow.ValidateInputs` at the agent's recipe entry; stub RecipeSource refusal test; narrowed `-run`).
- 2 (re-check): guard folded (entry helper sited in launchRunner's folder==nil branch and atop bindRecipeInputs, never recipeLaunch/recipeByID; typed-launch + fan_out refusal tests; `(*workflowSpawner).task` render test added to `-run`).
- 3: guard folded (unexported `validateSeed` returns the scoped list; no `SeedRefusedError{` in construct.go; `HOME=""` + `~/x` fixture over both seedConstructors).
- 4: guard folded (`wantSeeded` flip on the observe row; restore test kept over a held bad profile; widened comment grep; dead imports dropped).

## 1. ValidateInputs refuses every reserved placeholder name — ✅ DONE (2026-10-29)

NOTES (2026-10-29): the brief placeholder consts are built as `placeholderOpen + <Name>InputName + placeholderClose` (unexported `{`/`}` consts in inputs.go) rather than the approach's `"{" + <Name> + "}"`, which the item's own Acceptance grep `placeholder(...) += "\{` would match; the role phrases use a small `braced(name)` helper over the same consts, and SKILL_DIR's phrase quotes `domain.SkillDirToken` directly.
NOTES (2026-10-29): the reserved-name table extends `TestValidateInputsReservesTheApogeeName` (name kept, per the no-rename rule) and the exact `apogee` message, the case-sensitive near-miss (`Workflow_dir`, `Item`) and the `SkillDirToken` pin are three sibling tests in inputs_test.go.

**What:** Fix for `recipe-input-shadows-placeholder` (found 2026-10-10, confirmed 2026-10-29): an input named `workflow_dir`, `part_bytes` or `SKILL_DIR` passes validation and silently replaces a script stage's run-time placeholder; the names `claim`, `output` and `manifest` (filled only in the verify and merge leads, never bound from inputs) are reserved ahead of use.
**Regression guard.** Keep the ratified list of nine. `claim`/`output`/`manifest` (and `item`/`out`, skipped by the agent binder today) are reserved ahead of use, not shadowed: a recipe declaring one loads and runs at 65ebeaff and stops loading after this item, so the item's CHANGELOG entry says a recipe declaring any of the eight new names no longer loads, with the rename hint. The doc check is scoped to §Inputs, and no placeholder const is a bare `"{…}"` literal.
**Goal:** `internal/workflow` exports the one list of reserved input names (the nine in the header's ratified call), each with the phrase its refusal uses. `ValidateInputs` refuses each with a `Problem{Field: "inputs"}` naming the input; the `apogee` message is byte-identical to today's. `workflow`'s own brief placeholders (`{item}`, `{out}`, `{claim}`, `{output}`, `{manifest}`) are built from that list, so a new placeholder cannot be added without reserving its name. `docs/manual/workflows.md` §Inputs names every reserved name.
**Approach (assumed at the header base):**
- Beside `ApogeeInputName` in `internal/workflow/inputs.go`, add exported name consts for each reserved name and one exported accessor (e.g. `ReservedInputNames()`) returning name → role phrase; `ValidateInputs`' `ApogeeInputName` case becomes a lookup in it.
- `placeholderItem`/`placeholderOut` (`runner.go`) and `placeholderClaim`/`placeholderOutput`/`placeholderManifest` (`stages.go`) become `"{" + <NameConst> + "}"`.
- `SKILL_DIR`'s token lives in `domain.SkillDirToken`; a test pins `domain.SkillDirToken == "{{" + <SkillDir name const> + "}}"`.

## 2. The recipe binder and renderer read the reserved names from workflow — ✅ DONE (2026-10-29)

NOTES (2026-10-29): the entry check is `checkRecipeInputs` in recipe.go, which joins the ValidateInputs Problems' `Message` text with `; ` (not `Problem.String()`, which would prefix `field "inputs": `), so the refusal reads `could not run: input name "item" is reserved: …`.
NOTES (2026-10-29): `startBackgroundRecipe` (background.go, not in Files) calls `workflow.BindInputs` directly before reaching launchRunner. A reserved *required* input there is refused as `missing input: <name>` rather than as reserved. Any other reserved input is refused as reserved in launchRunner. Either way nothing is bound, so no shadowing door opens.

**What:** Recast at the regression check (2026-10-29). Depends on item 1. Completes `recipe-input-shadows-placeholder`: the agent side stops keeping its own lists of placeholder names.
**Regression guard.** Every recipe the agent runs, from any RecipeSource (the skills loader or an embedder's port), has its declared inputs checked by workflow.ValidateInputs at the agent's recipe entry before binding, refused with the same Problem text, so deleting reservedInputNames opens no shadowing door for an embedder recipe (ADR 0031); add a test where a stub RecipeSource recipe declaring input `item` is refused; narrow the Acceptance -run to the named recipe tests (e.g. 'TestBindPlanInputs|TestRender_|TestRecipe_AShippedScriptIsStagedAndRun') so the sandboxed confine_linux_test.go TestRecipe_* rows are not swept in.
The entry check is one helper, called in launchRunner's `launch.folder == nil` branch before `completeInputs` (every `bindPlanInputs` call goes through it) and at the top of `bindRecipeInputs`, so a reserved required input is refused before the Asker is asked; never in `recipeLaunch` (a false there demotes a typed `/id` to a body attach) or `recipeByID` (a folder rerun/resume, bound at base, resolves through it).
Add a `(*workflowSpawner).task` test: a `Stage.Prompt` over an `fstest.MapFS` body `audit {item} into {out}`, `spec.Item.Units` and `spec.Output` set, asserting the rendered brief, so swapping the item/out consts fails.
**Goal:** `internal/agent` holds no placeholder name of its own: `apogeePlaceholder`, `workflowDirPlaceholder`, `partBytesPlaceholder` and the `{item}`/`{out}` the workflow spawner fills are built from `internal/workflow`'s name consts; `reservedInputNames` no longer exists, and `inputReplacers` binds every input it is given (validation already refused the reserved ones).
**Approach (assumed at the header base):**
- `internal/agent/recipe.go`: rebuild the three render consts from the workflow name consts; delete `reservedInputNames` and its `continue` in `inputReplacers`.
- `internal/agent/workflowspawn.go` `(*workflowSpawner).task`: the literal `"{item}"`/`"{out}"` read the workflow consts.

## 3. One exported seed check in the engine — ✅ DONE (2026-10-29)

**What:** First half of `driver-lane-precheck-gap`: the engine's whole seed check (`validateGeneration`, then the sync-lane scope) becomes one exported function that construction itself calls.
**Regression guard.** `ValidateSeed` wraps an unexported `validateSeed(gen, workspaceDir) ([]domain.Reaction, error)` that already returns the `*SeedRefusedError`; `buildAgent` calls `validateSeed` for the scoped sync list, so construct.go builds no `SeedRefusedError{` of its own (Acceptance greps it). The unresolvable-`workspace:` fixture is a non-parallel test with `t.Setenv("HOME", "")` and `Workspace: "~/x"` — a plain bad path is scoped out, never refused (`scope.Resolve` fails only on a leading `~` with no home).
**Goal:** `agent.ValidateSeed(gen domain.Generation, workspaceDir string) error` returns nil or a `*SeedRefusedError` whose message is exactly what `New`/`Resume` return for the same seed; `buildAgent` refuses a seed only through it; the root package forwards it as `apogee.ValidateSeed`, pinned in `example_test.go`'s facade lists.
**Approach (assumed at the header base):**
- `(*Agent).scopeSync` becomes a free function over `(list, workspaceDir)` (it reads only `a.cfg.WorkspaceDir`); the method, if kept for `SetReactions`, delegates.
- `ValidateSeed` = `validateGeneration(gen)` then the scope check over `gen.Sync`, each wrapped `&SeedRefusedError{err: err}`; `buildAgent` (`construct.go`) calls it and still uses the scoped list.
- Update the `New` doc and the `buildAgent` comment to name `ValidateSeed`.
