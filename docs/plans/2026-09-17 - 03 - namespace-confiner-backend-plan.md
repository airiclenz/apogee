# Namespace confiner backend — implementation plan

**Goal:** Give Linux a second Confiner backend that fences terminal commands with user + mount namespaces through `bwrap`, selected when landlock is unavailable (Raspberry Pi OS, ENOSYS containers), so Auto confines there instead of gating every command. Capability honesty gains a *why* — the reason a backend cannot fence — spoken on every wording surface.
**Date:** 2026-09-17
**Status:** unexecuted
**Sized for:** ~200k-context host
**Base commit:** 0fc6bf17

**Ratified design calls (owner, 2026-09-17):**
- **No config key:** the backend is auto-selected only; "configurable" means the selector has two Linux rungs.
- **Launcher:** `bwrap` resolved on PATH at construction, ADR 0042 pattern (optional enhancement, graceful absence); native re-exec is out of scope.
- **Selector order:** landlock (ABI ≥ 1) → namespace (probe passes) → namespace `{false,false}` carrying both reasons. Landlock wins when both work (kernel-enforced, no external binary).
- **Type/label:** `namespaceConfiner` → "namespace" via `probe.BackendName`.
- **/dev shape:** `--dev /dev` (bwrap's minimal set); contract §2.3 property 2 amended — the namespace backend's write-exempt set is that device set, each node side-effect-free or the child's own terminal.
- **Reason surface:** `domain.ConfinementCaps` gains `Unavailable string`; `probe.CapabilityLine` renders it as ` · why: <reason>` when `FSWrite` is false.
- **Network:** empty `NetworkAllow` ⇒ no `--unshare-net` (open); non-empty ⇒ `--unshare-net` (deny-all, same effective semantics as landlock ABI 4). `NetworkEgress: true` when the probe passes.
- **Failure mode:** any construction-probe failure ⇒ `{false,false}` + reason; any `Confine`-time failure ⇒ `ErrConfinementUnavailable` (never unfenced).
- **Denial signature:** `Read-only file system` / `EROFS` join the kill-on-denial patterns.
