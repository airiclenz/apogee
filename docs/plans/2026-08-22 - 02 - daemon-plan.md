# The daemon — durable schedules over a declarative file — implementation plan

**Goal:** ship `apogee daemon` per [ADR 0034](../adr/0034-the-daemon-is-an-in-repo-subcommand-over-a-declarative-trigger-action-file.md):
an in-repo subcommand that reads `~/.apogee/daemon/schedules.yaml`, runs each entry's prompt on
its cycle through the shared runner (`internal/run`) and scheduler (`internal/schedule`), saves
every Firing into the shared sessions store, live-reloads the file, refuses a second instance,
and generates the host supervisor's unit via `apogee daemon install`.

**Date:** 2026-08-22
**Status:** unexecuted
**sized for:** ~200k-context host

## Ratified design calls

Decided by the owner (Airic Lenz) in the 2026-08-22 grill session that produced this plan:

1. **v1 scope: core daemon + `install`.** No `apogee daemon add` CLI sugar (the file is the
   contract), no `keep: N` retention, no `at:`/cron anchoring, no webhook triggers, no `mcp:`,
   no request-priority hint (waits on the Gateway). All stay future envelope keys per ADR 0034.
2. **Cycle semantics as the library already states them:** first tick one full cycle after the
   entry is (re)adopted; a daemon restart resets every phase; nothing fires at boot (restart-storm
   protection). No persisted last-fired state.
3. **Reload identity is the entry `name`.** Unchanged (name + spec deep-equal) → untouched,
   phase preserved. Edited → stop + re-add (phase resets). Removed → stopped; an in-flight
   Firing finishes (the library's `Stop` contract). Added → added. Any invalid entry — duplicate
   name included — rejects the WHOLE file with a logged reason; the previous set keeps running.
   No partial swaps.
4. **Schema (the v1 envelope):**

   ```yaml
   shutdown-grace: 10m          # optional, default 10m
   schedules:
     - name: nightly-audit      # required, unique
       on:
         cycle: 24h             # required, >= schedule.MinCycle
       run:
         prompt: "/code-audit internal/tui"   # required, non-empty
         workspace: ~/repos/apogee            # required, must exist at validate
         mode: auto             # optional: plan (default) | auto
         server: openrouter     # optional: a servers: entry name (ADR 0055)
         model: qwen/qwen3-72b  # optional: multi-model entries only (ADR 0055)
   ```

   `mode: auto` entries are validated against the host's Auto-eligibility ladder at load; an
   ineligible host rejects the file (all-or-nothing, the entry named in the log).
5. **Server binding per ADR 0055:** by name into `servers:`; `model:` refused on a
   launcher-fronted entry; the daemon never actuates a load — a Firing against an idle local
   server fails visibly in its record. `config.yaml` is read at startup only; rebinding servers
   is a daemon restart. `schedules.yaml` is the only live-reload surface.
6. **Modes are Plan/Auto only (ADR 0033 wholesale).** A Plan Firing's deliverable is the
   recorded answer (read in `/sessions`); an Auto Firing's is files in the workspace. Stated in
   the seeded template's comments.
7. **Single instance via an advisory OS lock** (`flock` / `LockFileEx`) held for the daemon's
   lifetime on a file under `~/.apogee/daemon/` — self-clearing on crash by construction; the
   PID inside is diagnostics only, never consulted.
8. **Shutdown:** first SIGTERM/SIGINT stops the clock, gives an in-flight Firing
   `shutdown-grace` (default 10m) to finish, then cancels (the runner saves what completed);
   a second signal cancels immediately; exit 0. Generated units derive their kill escalation
   from the grace (grace + 30s).
9. **`install` generates and instructs, never runs the supervisor's CLI.** It writes the unit
   file to the per-user location (or `~/.apogee/daemon/` for the Task Scheduler XML) and prints
   the one activation command. Re-running regenerates and says whether the file changed.
10. **First run seeds a commented `schedules.yaml` template** (embed, never overwritten); an
    empty set is valid — the daemon runs, logs "0 schedules", and watches. Logging is plain
    timestamped lines on stdout; the supervisor owns retention.

## Explicit non-goals (so nothing is re-derived)

Everything in design call 1; IPC of any kind; a daemon-side config.yaml watch; carry-over
context between Firings (a Mechanism, per ADR 0033); courtesy probing of server business
(ADR 0034 decision 9 — the Gateway owns supply).

## 1. `internal/daemon`: the schedules file — schema, parse, validate

**What:** new package `internal/daemon` holding the file model and its validation, pure and
host-free. Types mirroring the design-call-4 schema (`File{ShutdownGrace, Schedules}`,
`Entry{Name, On{Cycle}, Run{Prompt, Workspace, Mode, Server, Model}}`), parsed with strict
field checking (unknown keys are defects — this file is hand-edited, and a typo that parses is
a schedule that silently never changes). Validation returns ALL defects, not the first
(`ValidateServers`' reasoning, stated in its doc: a defect outlives the day it was written).

Rules: unique non-empty `name`; `cycle >= schedule.MinCycle`; non-empty `prompt`; `workspace`
required, `~`-expanded, must exist and be a directory; `mode` ∈ {plan, auto} (absent = plan);
`shutdown-grace` positive when present (absent = 10m). The config/host-dependent rules take
injected facts so the package stays pure: a `func(name string) (ServerFacts, bool)` lookup
(exists; is launcher-fronted) for `server:`/`model:` (ADR 0055: unknown server, or `model:` on
a launcher-fronted entry, are defects), and an `autoOK bool` for `mode: auto` entries.

**Files:** `internal/daemon/doc.go`, `internal/daemon/file.go`, `internal/daemon/file_test.go`

**Tests:** table-driven: a valid two-entry file parses to the expected model with defaults
applied; each rule above produces its named defect; multiple defects are all reported; an
unknown key is a defect naming it; `~` expansion resolves against the injected home.

**Acceptance:**
- `go build ./internal/daemon/`
- `go test ./internal/daemon/ -count=1`

**Commit:** `feat(daemon): schedules-file schema, strict parse, all-defects validation`

## 2. `internal/daemon`: the reload diff — name-keyed, phase-preserving

**What:** the pure diff design call 3 specifies, plus its application. `Diff(old, new []Entry)`
returns three name-lists — keep (deep-equal), replace (same name, changed spec), add/remove —
and `Apply` walks a minimal scheduler interface (`Add(schedule.Spec) (string, error)`,
`Stop(id) error`) plus the daemon's own name→id map to enact it: stop removed and replaced
entries, add new and replaced ones, touch kept entries not at all. Apply is what makes "editing
one schedule re-phases nothing else" true, so it is tested against a fake scheduler recording
the exact call sequence. The `Entry → schedule.Spec` mapping (name, cycle, prompt, mode) lives
here too — the daemon-only `run:` fields (workspace, server, model) travel to the Firing
composition via the name→Entry map, not through the library's `Spec`.

**Files:** `internal/daemon/diff.go`, `internal/daemon/diff_test.go`

**Tests:** table-driven diffs (kept/edited/removed/added, and an entry renamed = remove+add);
Apply against the fake: kept entries receive no calls, replaced entries stop-then-add, the
name→id map ends correct; an Add error surfaces without wedging the remaining operations.

**Acceptance:**
- `go test ./internal/daemon/ -count=1`

**Commit:** `feat(daemon): name-keyed reload diff that preserves unchanged phases`

## 3. Make the stat-poll file watcher reusable for a second file

**What:** the schedules watch reuses ADR 0041's watcher rather than growing a sibling. Today
the poll+settle mechanism lives in `internal/config` for `config.yaml` alone; give it a form a
second caller can hold — an exported constructor taking the path (and, for tests, a clock/stat
seam if it has one) — without changing `config.yaml`-watch behaviour at all: same 1s cadence,
250ms settle, mtime+size witnesses, same goroutine shape. Whether that is exporting the
existing type in place or lifting it into a small shared package is the implementer's call —
prefer whichever leaves ONE implementation with two callers and the ADR 0041 doc comment
intact.

**Files:** `internal/config/configwatch.go` (or a new shared home), its test file, the
`cmd/apogee` wiring that constructs today's watcher.

**Tests:** the existing watch tests keep passing unmodified in behaviour; one new test drives
the exported form against a temp file (write → settle → one report; two rapid writes → one
report).

**Acceptance:**
- `go build ./...`
- `go test ./internal/config/ ./cmd/apogee/ -count=1`

**Commit:** `refactor(config): expose the stat-poll file watcher for a second caller`

## 4. `internal/platform`: the advisory single-instance lock

**What:** design call 7. `platform.AcquireLock(path string) (release func(), err error)` —
open/create the file, take the OS advisory lock non-blocking (`flock(LOCK_EX|LOCK_NB)` on
unix, `LockFileEx(LOCKFILE_EXCLUSIVE_LOCK|LOCKFILE_FAIL_IMMEDIATELY)` on windows), write the
PID for `cat`-diagnostics, hold the descriptor until release. A held lock returns an error
naming the path and, best-effort, the PID read from the file — the caller turns that into
"apogee daemon is already running (pid N)". No liveness probing, no stale handling: the kernel
drops the lock with the process.

**Files:** `internal/platform/lock.go`, `internal/platform/lock_unix.go`,
`internal/platform/lock_windows.go`, `internal/platform/lock_test.go`

**Tests:** acquire → release → acquire succeeds; while held, a second independent acquisition
of the same path fails with the path (and pid) in the error — via a second descriptor where
the platform's semantics make that a real conflict, else a helper subprocess (the stdlib's own
idiom); release is idempotent.

**Acceptance:**
- `go build ./internal/platform/`
- `go test ./internal/platform/ -run 'TestAcquireLock' -count=1`

**Commit:** `feat(platform): advisory single-instance file lock`

## 5. The Firing composition: one validated entry → one run

**What:** `cmd/apogee/daemonfire.go` — the daemon's counterpart to `scheduleWiring.fire` and
`runHeadless`'s composition, built once at adoption per entry and handed to the scheduler as
its `Fire`. Per design call 5 / ADR 0055: resolve the entry's server (named `servers:` entry,
else the startup default `selectStartupServer` yields), overlay `model:` where legal, resolve
the per-model half through `rebindSpecFor` exactly as headless does, leave Asker/Presenter nil
and MCP unwired, run through the `runOnce` seam, and map the result onto `schedule.Outcome`
(answer, denials, usage, record id) so the Notify log can state what happened. Auto entries
compose the Confiner via the `newConfiner` seam — same gate headless applies, already proven
at validate-time by item 1's `autoOK` fact. No launcher actuation anywhere on this path.

**Files:** `cmd/apogee/daemonfire.go`, `cmd/apogee/daemonfire_test.go`

**Tests:** with `runOnce` stubbed: a plain-server entry composes endpoint/model/key from its
named entry; `server:` absent falls to the startup default; a launcher-fronted entry sends to
its endpoint as-is (no actuation call sites exist to stub — assert by construction: the test
compiles against a composition that takes no launcher seam); Plan and Auto map to the modes
`run.Once` receives; the Outcome carries the stubbed result's answer and denial count.

**Acceptance:**
- `go build ./cmd/apogee/`
- `go test ./cmd/apogee/ -run 'TestDaemonFire' -count=1`

**Commit:** `feat(daemon): per-entry firing composition over the shared runner`

## 6. `apogee daemon`: the command — startup, lifecycle, logging

**What:** `cmd/apogee/daemon.go`, registered in `subcommands()` after `headless`. Startup:
resolve config (`config.ApplyConfig`, `--config` flag as headless has); ensure
`~/.apogee/daemon/`; seed `schedules.yaml` from `//go:embed cmd/apogee/defaults/schedules.yaml`
when absent (never overwrite — the `config.yaml` seeding precedent; template content per design
calls 4/6/10: commented schema reference, plan-vs-auto guidance, `shutdown-grace`, one commented
example); acquire the item-4 lock or exit with "already running (pid N)"; parse+validate via
item 1 (defects → log every one, exit non-zero — at startup there is no previous set to keep);
build `schedule.New` with item 5's Fire, `Gate: nil`, `Notify` → one timestamped stdout line
per event, real clock; adopt the initial set via item 2's Apply.

Lifecycle per design call 8: run until SIGTERM/SIGINT; first signal logs, stops accepting
ticks (`Scheduler.Close` on a grace timer), waits up to `shutdown-grace` for an in-flight
Firing, then cancels; second signal cancels immediately; exit 0 on a clean stop, 1 when
startup was refused (lock, config, invalid file). Foreground only — no self-daemonizing.

**Files:** `cmd/apogee/daemon.go`, `cmd/apogee/defaults/schedules.yaml`,
`cmd/apogee/daemon_test.go`, `cmd/apogee/subcommands.go`

**Tests:** with seams stubbed (lock, clock, runOnce): first run seeds the template and an
existing file is never overwritten; an invalid file at startup logs every defect and exits
non-zero; a valid file adopts every entry (fake scheduler or real one with a fake clock);
the notify line format is pinned for fired/completed/failed/skipped; SIGTERM with no Firing
in flight exits promptly; `apogee --help` lists `daemon`.

**Acceptance:**
- `go build ./...`
- `go test ./cmd/apogee/ -run 'TestDaemon' -count=1`

**Commit:** `feat(daemon): the apogee daemon subcommand — lock, seed, adopt, run, shut down`

## 7. Live reload: watch, validate, swap

**What:** wire item 3's watcher onto `schedules.yaml` inside the daemon loop. On a settled
change: parse+validate; invalid → log every defect plus "keeping the previous N schedules",
change nothing; valid → item 2's diff+Apply, then log one line naming the added, replaced and
removed entries (and "no change" when the edit was cosmetic). `shutdown-grace` changes take
effect on the next shutdown. The reload path shares the startup adoption code — one adopt
function, called with an empty previous set at startup — so the two cannot drift.

**Files:** `cmd/apogee/daemon.go` (or `daemonreload.go` if it earns its own file),
`cmd/apogee/daemon_test.go`

**Tests:** drive the watcher seam directly: an edit adding one entry logs it and leaves the
untouched entry's schedule id unchanged (phase preserved — assert via the name→id map); an
edit breaking the file keeps the previous set and logs the defects; a removed entry stops.

**Acceptance:**
- `go test ./cmd/apogee/ -run 'TestDaemonReload' -count=1`

**Commit:** `feat(daemon): live reload of schedules.yaml with all-or-nothing swap`

## 8. `apogee daemon install`: generate the supervisor unit

**What:** design call 9. A `daemon install` child command that detects the host OS and writes
the per-user unit — `~/.config/systemd/user/apogee-daemon.service` (Linux),
`~/Library/LaunchAgents/com.airiclenz.apogee.daemon.plist` (macOS),
`~/.apogee/daemon/apogee-daemon-task.xml` (Windows) — from an embedded template filled with
the absolute binary path (`os.Executable`), the `--config` dir when one was passed, and the
kill escalation derived from the file's `shutdown-grace` + 30s (`TimeoutStopSec`; the
launchd/Task-Scheduler equivalents). It then prints the one activation command
(`systemctl --user enable --now apogee-daemon` / `launchctl load …` / `schtasks /create /xml …`).
Re-running regenerates and reports changed/unchanged. Generation is pure and OS-parameterized,
so all three templates are golden-tested on any host.

**Files:** `cmd/apogee/daemoninstall.go`, `cmd/apogee/daemoninstall_test.go`, embedded
templates under `cmd/apogee/defaults/`

**Tests:** golden output for all three targets (fixed fake binary path, grace, home); the
derived escalation follows a non-default `shutdown-grace`; re-run on an unchanged file says so;
the printed activation command per OS is pinned.

**Acceptance:**
- `go build ./cmd/apogee/`
- `go test ./cmd/apogee/ -run 'TestDaemonInstall' -count=1`

**Commit:** `feat(daemon): install generates the per-OS supervisor unit and prints activation`
