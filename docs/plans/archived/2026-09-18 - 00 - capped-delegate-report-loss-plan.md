# Capped delegates keep their report — engine fold, tail-fenced wrap-up, one write, structural step notice, continue

**Goal:** A delegate that hits a bound (step, token or time cap) never hands its parent a fabricated tool dump: the engine folds the child's conversation into a summary the parent always receives, the wrap-up ask sits where the model reads it, one `write_file` survives the wrap-up, the step-budget notice fires for every delegate, and the parent can continue a capped delegate from that fold instead of re-spawning it.
**Date:** 2026-09-18 · **Status:** unexecuted · **Sized for:** ~200k-context host
**Base:** `6635f881`

**Ratified design calls** (owner, 2026-09-18, unless marked writer):
- **P1 placement:** the wrap-up directive is fenced onto the closing tool result of the capping Turn; the system-prompt copy remains only as the fallback when the tail is not a tool result. (Both wires already degrade a tool message to user role on a tool-less request, so on the plain wrap-up the fence reaches the model as the tail of a user message — the tail-message variant and the fence coincide; no model-profile switch.)
- **Engine fence header (writer):** engine-structural text on a tool result uses its own fence `[engine — <topic>]` … `[end engine — <topic>]` on the advice ledger, never an `AdviceSpan` (whose header names a Reaction id).
- **P3 body:** on every bound the result body is the engine fold under `[engine summary]`, followed by the child's closing reply under `[delegate's closing report]` — or, when item 3 judges it a non-report, under `[delegate's closing report — read as narration, not a finding]` (P2 below).
- **P5 classing:** the step-budget notice is engine-structural at depth ≥ 1 — on everywhere including Bypass; the `step-budget-notice` key, `/settings` row, `Options`/`Config`/`Generation` fields and reserved id are removed; ADR 0077 gets a superseding note.
- **P4 orientation (writer):** the "pass it as `output_path`" sentence lives in the `sub_agent` tool description only; the Delegations orientation bullet is seat-gated and positional, so it is not touched.
- **P6 state:** the parent retains, in memory only, `{task, name, tools, output_path, fold, closing report, bound}` per capped child until its Exchange ends; `continue` spawns a fresh child whose opening context is the task plus the fold. Nothing is serialised — ADR 0022 D8 and ADR 0013 §5 stand.
- **P6 handle:** `sub_agent` gains `continue: "<name>"`; keyed by delegation name, latest capped child with that name wins; unknown name → error result naming the retained names.
- **P6 budget:** each continuation is a new Run with `min(max_steps, delegate-max-steps)` steps — "only lowers" stays true per Run; no engine limit on continuations.
- **P5 re-arm on fold (owner, 2026-09-19):** a compaction fold re-arms the step notice as it re-arms the fill notice; after a fold it fires on the next tool result once `used >= threshold` — at most one live copy in the history, never a second while the first survives.
- **P2 non-report (owner, 2026-09-18):** a non-report is never dropped — variant head + `[engine summary]` + fold + `[delegate's closing report — read as narration, not a finding]` + the text; blank text is item 2's wordless path, never a non-report.
