# Project config and allow rules — plan

**Goal:** a committable `<Project root>/.apogee/config.yaml` layered over the global config, persisted Allow rules for `terminal` and MCP servers whose project entries are live only by Adoption, and a user-configurable `dangerous-rules:` key — as ADR 0096 decides.

**Status:** unexecuted
**sized for:** ~200k-context host
**base:** 9bfe92fb
**Closes:** apogee-089; apogee-zlg

**Sources:** `docs/adr/0096-project-config-grants-are-live-only-by-adoption.md` (authoritative); `CONTEXT.md` — Allow rule, Project root, Project config, Adoption; ADR 0076 D10/A2; ADR 0012; ADR 0049 §4/§6; ADR 0041; ADR 0031.

**Ratified design calls** (owner, 2026-10-10 grill):
- **Rule scope:** project rules by default (approval pane); global rules hand-written in `~/.apogee/config.yaml`, live as written.
- **Matching:** word prefix; every simple command must match; redirects, `$(…)`, backticks, heredocs, unparseable lines, wrappers and `NAME=value` prefixes ask; `cd` inside the workspace matches; no wildcards; never on Windows `cmd`.
- **Tools covered:** `terminal` and MCP servers only; file edits get no rules.
- **Where a rule answers:** ordinary gates (ask-before, allow-edits, Auto's unconfinable gate); never refusals, forced looks or a Reaction's ask/deny; the engine applies rules for every Driver; today only the TUI reaches an ordinary gate (owner, 2026-10-10).
- **Project root:** nearest `.apogee/` from the workspace up to the git top-level, never `$HOME`; workspace otherwise; `.apogee/skills` follows it.
- **Location:** rules live in the repo file; fingerprints in `~/.apogee/workspaces/<sha256>.yaml`; file tools Tier-1 refused on `.apogee/config.yaml`; `.apogee/skills/` stays writable.
- **Adoption UX:** startup pane, re-offered at the next turn boundary on change; adopt / not now / reject; unattended Drivers stay silent; the daemon reads no Project config (owner, 2026-10-10); `apogee project adopt`.
- **Key classes:** global-only (default), project-param, tighten-only, granting. MCP servers and Reactions in the project file are out of scope.
- **Approval pane:** fourth choice "Always in this project…" with an editable suggested rule; interpreters suggest the script path.
- **/settings:** source per row (`default|global|project|env|flag`); save target asked for project-capable keys; an *Allow rules* section.
- **YAML:** `allow: {terminal: [..], mcp-servers: [..]}`; `dangerous-rules: {add: [{id, pattern, tier: ask|refuse, reason}], remove: [ids]}`, `remove` global-only.
- **CLI:** `apogee project adopt`. **Visible line:** "allowed by project rule `go test`" / "allowed by global rule `…`".

**Standing requirements:**
- skills: coding-standards
- Every new user-facing key is documented in `docs/manual/configuration.md` by the item that adds it (`TestManualDocumentsEverySettingsKey`).
- No new headless event kind and no new `APOGEE_*` variable (pinned counts).
- Every new file is named in its package's `doc.go` (`TestDocMapNamesEveryFile`).

**Out of scope** (follow-up beads): MCP servers and Reactions in the project config; `NetworkAllow` / `confine-writable-paths`; the rest of the `apogee-9d8` tool × mode matrix; per-firing Project config layering in the daemon.
