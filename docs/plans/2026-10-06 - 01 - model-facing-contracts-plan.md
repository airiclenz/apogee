**Ratified design calls** (owner, 2026-10-06):
- **Breaker streak:** trips after threshold back-to-back identical (tool+args) failing executed calls; any executed call with another signature, success or failure, resets every streak and re-arms every tripped signature; refusals (breaker, dangerous-action guard, mode, approval denial) are not executions and change nothing; `Guards.ForSubAgent` isolation unchanged.
- **Breaker wording:** refusal Reason `circuit-breaker open: this exact call failed <threshold> times in a row`, Hint `run a different step first (fix the cause or change the arguments); the call is allowed again after another call runs`; the trip ErrorEvent drops "further identical calls will be refused" and states the re-arm rule.
- **Malformed native call:** parsed per call; a call with a name and an id whose arguments are not a JSON object stays in the Response marked malformed (parse error + raw text); no name or no id keeps `dispatchableCalls`' drop-and-report; no id is ever synthesised.
- **Malformed call route:** tool-call-repair re-streams with a correction naming it; when it does not fire, the valid siblings dispatch and the call is answered `arguments were not valid JSON (<parse error>); you sent: <first ~200 chars of raw>`; its committed arguments are `{}` on every wire.
- **Custom-regex example:** derived from the `name`/`args` groups (`(?<` and `(?P<` spellings, balanced parens), delimiter regex syntax rewritten, used only if it round-trips through the profile's own parser; the generic `<tool_call>name({...})</tool_call>` fallback is removed.
- **`tool-call-example:`:** custom-regex-only profile key, one literal call validated at load through the pattern, shown verbatim and winning over derivation; load refuses a pattern lacking `name`/`args` or with no usable example, naming the key and quoting the failing example.
- **Malformed call in dispatch:** answered right after the registry lookup (an unknown tool's refusal wins), before the argument-key checks; ToolCallEvent still emitted; pre-tool-exec Moment skipped; an AuditEvent emitted like every call decision (`security.AuditMalformedArguments` = `"malformed-arguments"`); a mode-withdrawn tool's malformed call gets the malformed error.
- **Malformed call surface:** no ErrorEvent on the fallback path (the error tool-result row is the user's surface); the `dispatchableCalls` no-name/no-id drop-report stays.
- **Custom-regex probe:** the load check derives and round-trips the fixed probe call `read_file {"path": "src/main.ts"}` (shown in the load error); at runtime the menu tools are tried in order, and the probe example is shown if none round-trips.
- **Custom-regex args:** a non-empty args group that is not a JSON object is a malformed call on the native route; an empty group stays `{}`.
- **Two-Turn malformed exit:** when the previous committed Turn of the Exchange carried a malformed-marked call and the current response still carries one after the repair retries are spent, the Exchange ends the pre-item way — the calls are dropped, a `"processing"` ErrorEvent names why (the Exchange-ending fault, distinct from "no ErrorEvent on the fallback path"), and the Turn is a final no-tool reply. One malformed Turn is answered and recovered; two in a row stop. Item 4 owns it.
- **Resumed malformed call:** after a session snapshot/resume mid-Exchange, a committed malformed call reloads with arguments `{}` (the `json:"-"` marker is not persisted) and keys as `{}` for the loop breaker; accepted, no snapshot format change.
- **Repair wording for broken JSON:** the correction reuses apogee-sim's `arguments are not valid JSON: <error>` that `validateArguments` (internal/floor/repair.go) already sends; no new tool-named line.

## 1. The circuit breaker counts only back-to-back identical failures — ✅ DONE (2026-10-07)

NOTES (2026-10-07): TestGuards_PreExecute_RefusalChangesNothing lives in internal/security/guard_test.go, a file the item's **Files:** line did not list (guardCall and the other TestGuards_ tests live there).
NOTES (2026-10-07): the breaker's refusal Reason (guard.go PreExecute) and the trip ErrorEvent / refusal text in internal/agent/dispatch.go still say "identical tool call has failed repeatedly" / "further identical calls will be refused"; item 2 owns that wording, so it is left untouched here.

**What:** Fixes audit Medium "Circuit breaker trips on interleaved failures, then refuses the call forever".
**Goal:** `security.CircuitBreaker` trips a signature only after `Threshold()` failing `Record` calls of that signature with no other signature recorded between them; a `Record` of any other signature, failed or not, zeroes every streak and clears every tripped signature; a refused call is never recorded, so a refusal changes nothing.
**Approach (assumed at the header base):** In `internal/security/circuitbreaker.go`, replace the per-signature `failures` map with the last recorded signature and its streak: `Record` compares the incoming signature with the last one; a different one resets the streak and `tripped` before counting, and a success of the same one zeroes the streak. `Tripped` keeps its contract (read by `Guards.PreExecute` before execution); `Guards.ForSubAgent`'s fresh breaker is unchanged. Record order is the order `Record` is called in — a reply's calls in emitted order (a pooled delegation group records at commit, in call order). The type, `Record`, `DefaultCircuitBreakerThreshold` and `NewCircuitBreaker` docs state the back-to-back rule.
**Regression guard.** Every prose line describing when the breaker trips or clears as per-signature for the Agent's lifetime, or cleared only by that signature's success, is rewritten to the back-to-back rule (doc.go's "The runaway halt" paragraph included): `grep -rn -i 'streak\|consecutive\|success clears\|circuit.\?breaker' internal/security internal/agent --include=*.go`. `TestCircuitBreaker_DistinctCallsIndependent`, `TestCircuitBreaker_SuccessClearsATrippedSignature` and `TestCircuitBreaker_ConcurrentUse` encode the old rule and are rewritten: `ConcurrentUse` keeps its `-race` interleaving, drops the per-signature edge assertion (cross-signature independence is the reversed rule), and asserts one deterministic end state (a final single-goroutine A✗×3 trips). This supersedes the CHANGELOG.md entry (~9665-9671) that has `ConcurrentUse` pin "concurrent traffic never leaks across signatures"; the item's changelog entry says so.
