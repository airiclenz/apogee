# Hooks — observe-only Driver-side reactions to engine events (bead `apogee-20w`, ADR 0073)

**Goal:** a global `hooks:` list in `~/.apogee/config.yaml` runs an argv command or POSTs a webhook when one of five post-hoc Hook events fires, composed from one `internal/hooks` library at every root (TUI session, headless, daemon Firing, TUI `/schedule` Firing). Two additive engine event variants (`TurnEvent`; two-phase `ApprovalEvent`) make the Turn boundary and the waiting Approval observable. Nothing a Hook does reaches the model, the conversation or the Session record.

## 4. `internal/hooks` — the Runner (sink decorator, queues, reporter, reload, close) — ✅ DONE (2026-09-06)

NOTES (2026-09-06): consequential edit — internal/hooks/doc.go: made necessary by adding runner.go, whose "files, one line each" package map would otherwise be incomplete.
NOTES (2026-09-06): `New`/`Replace` run `ValidateAll` over the list and refuse an active Hook with no `Options.Exec`; the plan named neither, but `New` returns an error and workspace resolution alone cannot justify it — a Hook with a zero `Timeout` would otherwise make `context.WithTimeout` expire instantly.
NOTES (2026-09-06): a failure whose cause is the Runner's OWN shutdown (the generation's context was cancelled by `Close` past its grace, or by a `Replace` drain) is not reported — it is our doing, not the Hook's, and would put a failure line on every shutdown that killed a slow script.
NOTES (2026-09-06): `Replace` starts the new generation with a clean write-correlation map; a write whose tool result had not yet arrived at the swap fires no `file-changed` event. Copying the old matcher's pending map would mean reading it from another goroutine while `Emit` writes it.
NOTES (2026-09-06): `Options.Report` is documented as non-blocking and non-re-entrant — it is called from a worker goroutine on a failure and from `Emit`'s goroutine on a queue drop's first occurrence, and the Runner serializes the calls under its own mutex so a Driver's notifier needs no lock of its own.

**What.** `internal/hooks/runner.go`: `type Options struct{Inner domain.EventSink; Workspace string; Schedule *ScheduleRef; Report func(string); WriteTarget func(domain.ToolCall) (string, bool); Exec Executor; Now func() time.Time}`; `type Executor interface{ Run(ctx context.Context, h Hook, p Payload) error }` (item 5 supplies the real one; a fake serves the tests here); `New(hooks []Hook, o Options) (*Runner, error)`; `(*Runner) Emit(domain.Event)` forwards to `Inner` first (nil-safe, like `eventTap.Emit` and `pruneNoticeSink.Emit`), then matches and enqueues — never blocks: the per-Hook queue is a buffered channel of depth 64 and a full queue drops the newest and bumps that Hook's drop counter (`Emit` runs under the engine's tree-wide mutex, `construct.go:154-158`). One worker goroutine per active Hook (workspace filter evaluated when the set is built: `Hook.Workspace` resolved vs `Options.Workspace`, ratified call C), events in order, `Exec.Run` under `context.WithTimeout(h.Timeout)`. `(*Runner) Replace(hooks []Hook) error` swaps the active set atomically (`atomic.Pointer` over the set) and drains the old workers in the background with the same grace. `(*Runner) Close(ctx) error` stops intake, waits for every worker up to ctx, then cancels what is still running (`sync.Once`; copy the shape of `console.Process.Close`, `internal/console/process.go:188-210`). Reporter lines: `hook <name> (<event>): <failure>` de-duplicated per the header's rule; `hook <name>: dropped 1 event (queue full)` on the first drop and `hook <name>: dropped N events` at Close. Facade: `apogee.go` re-exports `Hook`, `HookEvent = hooks.Event`, `HookOptions`, `HookRunner`, `HookPayload` and `NewHookRunner = hooks.New`. Depends on item 3.

**Regression guard.** `Runner.Emit` forwards to `Inner` and returns without matching when the active set is empty, and rebuilds the matcher's subscribed set on `New` and `Replace`; a runner test asserts the injected `WriteTarget` is never called with zero Hooks and is called once a `file-changed` Hook is `Replace`d in.

**Tests.** With a fake `Executor` that records `(Hook, Payload)` and can block on a channel: order preserved per Hook; two Hooks run concurrently (both blocked, then released); 64+1 events on a blocked Hook → one drop report and the 65th payload absent; `Emit` returns while the executor is blocked (assert with a deadline); `Inner` receives every event regardless; a Hook whose `Workspace` differs receives nothing; `Replace` stops the old Hook after its in-flight job and starts the new one; `Close` with an expired ctx returns promptly and cancels the executor's ctx; an `Executor` error is reported once, a second identical error is not, and after a success the third is; with zero Hooks `Emit` forwards every event and the injected `WriteTarget` is never called, and it is called once a `file-changed` Hook is `Replace`d in. `go test -race` on the package.
