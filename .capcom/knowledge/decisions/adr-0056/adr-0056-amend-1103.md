---
title: "ADR 0056 amendment of 2026-11-03: the work-tree probe's own budget and bounded retry"
---

Decision 4's 2 s contract no longer governs the floor's **work-tree probe** — the `rev-parse --is-inside-work-tree --show-toplevel` run ahead of a subprocess call's first snapshot; it still governs every **snapshot**. The probe ran once per Agent (`sync.Once`) under the snapshot's 2 s timeout, so on a slow or loaded box one timed-out or cancelled first probe turned the tracked-file mutation floor off for the Agent's whole life — a fixed deadline failing a healthy run, which AGENTS.md's slow-machine rule calls a bug.

Now the probe has its own budget, `treeProbeTimeout` (30 s, `internal/agent/treesnapshot.go`), and latches only a **definitive** answer: a work tree; git exiting non-zero (not a work tree); git absent; a fenced (planted) git; a repository refused for its command-valued config (`gitexec.CommandConfigRefusal`). A run that gave **no answer** — it timed out or wedged its drain (`gitexec.ErrIncomplete`), its command-config check did not complete (`gitexec.CommandConfigIncompleteRefusal`, also `ErrIncomplete`), or its ctx was done (a cancelled Turn, the probe's own deadline) — latches nothing, so the next subprocess call probes again; after `treeProbeTransientLimit` (3) such runs in a row the probe latches "no" for the Agent's life, so a git that never answers costs at most three probe budgets. A snapshot's 2 s timeout, workspace-root cwd and silent skip on any failure stand unchanged. Rejected: probing on every call (a git per call for a non-repository root) and an unbounded retry (a wedged git would cost every call 30 s). (2026-11-03, docs/plans/2026-11-03 - 00 - code-audit-fixes-plan.md item 10)
