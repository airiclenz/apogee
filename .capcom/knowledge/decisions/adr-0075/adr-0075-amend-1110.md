title: "ADR 0075 amendment of 2026-11-10: an upstream_loading kind"
---

One addition within `v:2` under decision 10. A kind a reader does not know is one it ignores, so it does not bump the version.

**A thirtieth kind, `upstream_loading`.** Decision 4's list gains `upstream_loading`, written for `domain.UpstreamLoadingEvent`: a model call found its server still loading its model — the HTTP 503 `Loading model` reply llama-server sends while it loads — and is waiting the load out rather than failing. `data` carries `server`, the bound `servers:` entry's name (`""` when the host names none), and `model`, the model the call asked for. The engine emits it once per model call, as that call's wait starts, stamped with the calling Agent's envelope identity, at every depth and for compaction's summary call as well as a Turn's; a call on an entry naming a `fallback:` list never waits (ADR 0105), so it writes none. It is observation only, like `upstream_attempt`: nothing in it reaches history or the model. The event's own sentence, `<server> is still loading its model (HTTP 503) — waiting up to 10m` (`this server` where no entry names it), is what every Driver shows. The vocabulary is thirty kinds, twenty-eight Event variants plus the two frames, with the new kind placed before the frames in `Kinds()`. This supersedes the "twenty-nine" of `adr-0075-amend-1109` by amendment, not by rewrite.
