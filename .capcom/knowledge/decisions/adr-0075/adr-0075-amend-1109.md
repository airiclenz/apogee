One addition within `v:2` under decision 10. A kind a reader does not know is one it ignores, so it does not bump the version.

**A twenty-ninth kind, `mcp_server`.** Decision 4's list gains `mcp_server`, written for `domain.MCPServerEvent`: one MCP server's connection lifecycle (ADR 0111 decision 8). `data` carries `server`, `transport`, `project` (the server came from the Project config), `phase` — `dialling`, `connected`, `failed` or `disconnected` — then `tools` (the tool count on `connected`), `cause` (the failure's text on `failed`), `kept` (`true` on a `failed` reconnect while the previous connection still serves) and `reason` (`removed` or `denied`, on `disconnected` only). Per decision 3 every member is always present, its zero where the phase does not set it. A reconnect is `dialling` then `connected` or `failed`, with no `disconnected` between.

It is the first kind the engine never emits: the composition root that owns the MCP dials emits it through the engine's serialised sink, and the engine stays MCP-blind. Its envelope identity is therefore always zero — a server belongs to the session, not to an agent, a Turn or a delegation. Only the interactive session's Event journal writes it; a headless `--format json` stream never carries it, though the encoding is total and a Writer handed one writes it. The server name, transport and cause are untrusted text, stripped of escapes where a Driver renders them. The vocabulary is twenty-nine kinds, twenty-seven Event variants plus the two frames, with the new kind placed before the frames in `Kinds()`. This supersedes the "twenty-eight" of `adr-0075-amend-1108` by amendment, not by rewrite.
