One addition within `v:2` under decision 10. A kind a reader does not know is one it ignores, so it does not bump the version.

**A thirty-first kind, `question`.** Decision 4's list gains `question`, written for `domain.QuestionEvent` (`adr-0076-amend-1124`): a question was put to the human and is waited on — the `ask_user` tool's, a recipe's prompt for a required input its launch text left unbound, or a Workflow `ask` stage's, a background one's stamped with the Turn that launched the workflow. `data` carries `question`, its text; `choices`, the answers offered beside the free-text box, always an array (`[]` for a free-text question, never `null`); and `multi_select`, whether several may be picked. Like an `approval` line's requested phase it is written before the answer; the answer is the asking call's own result, so there is no answered line. The question text is untrusted display text. The engine emits the Event only where a human can be asked — where an Asker is configured — so in practice only an interactive session's Event journal, or an embedder that supplies an Asker, writes the line: `apogee headless --format json` never carries it, since a headless run has nobody to ask. The TUI folds it as nothing (the question is already on screen as its prompt). The vocabulary is thirty-one kinds, twenty-nine Event variants plus the two frames, with the new kind placed after `upstream_loading` and before the frames in `Kinds()`. This supersedes the "thirty" of `adr-0075-amend-1110` by amendment, not by rewrite.
