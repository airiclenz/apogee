---
title: "ADR 0104 amendment of 2026-11-13: the pane says what the pin does not cover"
---

Decided by the owner on 2026-11-13 and shipped in the urgent defects and doc truth run (docs/plans/2026-11-13 - 00 - urgent-defects-and-doc-truth-plan.md, item 9), from the code audit of 2026-11-10 (docs/reviews/code-audit-2026-11-10.md, the adoption pin and the adopted launcher). It amends decision 11 and leaves decision 4 unchanged.

Decision 4 pins the files an entry's argv and `env:` values name, and nothing else. A launcher such as `npm`, `make`, `node .` or `python -m` reads files no argv element names — a `package.json`, a `Makefile`, an imported module, a directory it walks — and an edit to any of them runs after adoption without a re-ask. The manual and this record said so; the adoption pane did not, so the human ruling on the pane could assume the pin covered what the program would do.

Decision 11 now adds one line to the body of every MCP server and reaction pane, after the pinned files, or as a part of its own when no file is pinned: `not pinned: anything it reads or runs beyond these`, drawn dim. Every server and reaction pane draws it, including an `endpoint:` server and a `gate:`-only reaction that spawn nothing, because what the pin covers is the same statement for every entry. An Allow rule's pane has no body and draws no such line. `apogee project adopt` prints it plain as the body's last line. The layout is in docs/layout/user-questions-layout.md §Adoption pane.

Two wider pins were considered and rejected:

- **Pin the launcher's well-known manifests** (`package.json`, `Makefile`, `go.mod`, `pyproject.toml`). The list never ends: each launcher reads its own files, the files those name, and modules found by search paths, so a pin over a fixed list would cover some reads and not others while appearing to cover them all. That is the false assurance the disclosure removes.
- **Hash the Project root's tree.** Every edit anywhere in the repository would move the pin, so every commit, branch switch and the model's own edits would re-propose every adopted entry. A re-ask that fires on every change trains the human to answer yes without reading, which defeats the pane.

What a script and the programs it starts read stays the human's to review before adopting, as the manual's "What adopting a script means" says.
