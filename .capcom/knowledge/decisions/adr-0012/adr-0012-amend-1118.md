---
title: "ADR 0012 amendment of 2026-11-18: a repo-local merge driver is neutralised per call, and only a content merge is refused"
---

**Why now.** Amendment 0906 rests the **RO-subproc** class on, among other bounds, "the refusal of a
repository whose own config names a program git would execute". Until now that refusal was whole:
one repo-local command-valued key cost the repository every git call apogee makes — the model's git
tools, the tree-snapshot floor, the footer's git segment and its actions. One member of the class
made that refusal land on ordinary repositories: a merge driver (`merge.<x>.driver`), which capcom
tells its users to register with a plain, repo-local `git config`, and which git runs only on a
content merge. A repository carrying one lost its git tools for a key none of apogee's reads can
reach (issue `git-refusal-silent-footer`; plan
`docs/plans/2026-11-18 - 00 - git-refusal-silent-footer-plan.md`, items 1–5).

**(a) A repo-local merge driver is neutralised on every call.** When the probe finds merge drivers
and no other command-valued key, gitexec admits the call and adds one `-c merge.<x>.driver=` pair
per driver ahead of the subcommand (`judgeCommandConfig`, `internal/gitexec/gitexec.go`). An empty
driver value makes git print `cannot run :` instead of executing anything, and every read verb still
exits zero. A driver name whose subsection holds a `=` cannot be overridden that way — git splits a
`-c` argument at its first `=` — so it stays in the refusing class below. A merge driver in the
operator's global config is on the other side of the trust boundary and still runs, as before.

**(b) A merge-capable argv is refused with a sentence that names the key.** An argv whose job is a
content merge — `rebase`, `cherry-pick`, `revert`, `am` and `merge-tree` always; `merge` and `pull`
without `--ff-only`; `stash apply`, `pop` and `branch`; `checkout` and `switch` with `-m` /
`--merge`; `apply` with `-3` / `--3way` — is refused with `MergeDriverRefusal`, which names the verb
and the driver keys and says every other call still runs with the drivers neutralised. Of the argv
apogee runs today, only the footer's `rebase onto upstream` is one. An argv carrying `--abort` or
`--quit` unwinds and merges nothing, so it is never merge-capable (`mergeCapableVerb`). **Security
rests on the override, not on this list:** the list exists only so a merge fails with a clear
sentence instead of git's `cannot run`; a verb missing from it costs a confusing error, never an
execution.

**(c) Every other command-valued key still refuses the repository.** A credential helper, a filter
or diff driver, an `sshCommand`, a pager, an editor, a proxy, a remote helper (`remote.<n>.vcs`) —
any of them, alone or beside merge drivers, refuses every git call with `CommandConfigRefusal`,
naming every key, exactly as amendments 0906 and the ADR 0049 notes describe. Neutralising those
classes is out of scope. `gitexec.IsCommandConfigRefusal` recognises either standing refusal, so a
caller tells a refused repository from a failed git call there, never by matching the sentences.

**(d) `merge.<x>.driver` stays in the probe source — an exception to the split rule.**
`adr-0049-amend-1103` and `adr-0049-amend-1114` split the program-reaching keys: a key apogee's own
git can reach goes in the probe source (`security.GitCommandConfigNameSource`); a key the git hosts
already neutralise per verb goes in the shell write view's suffix only, so the probe does not cost a
repository its git tools for it. A merge driver is now neutralised per call too, yet it stays in the
probe source: the override has to name each driver's own subsection, and the probe's listing is what
names them. It no longer costs the repository its git tools, which is what the split rule guards
against, so the exception changes nothing the rule protects. The shell write view, built from the
same source, still names `.git/config` for a `git config` line that sets one, as amend-1103 says.

**(e) Tighten or loosen.** This is a loosen in reach — a repository that was refused outright now
runs every git call but a content merge — and the core invariant still holds: no repo-local merge
driver can run under apogee's git, because none is ever left with a value to run. The RO-subproc
bounds of amendment 0906 stand unchanged; what bounds a merge driver is now the override rather than
the refusal. The footer's side of the same change — a refused repository shown, not hidden — is
`adr-0108-amend-1118`.
