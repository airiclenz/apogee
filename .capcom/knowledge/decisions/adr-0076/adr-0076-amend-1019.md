---
title: "ADR 0076 amendment of 2026-10-19: the session-started boundary and its advise slot"
---

Grilled and ratified by the owner on 2026-10-19 for plan
`2026-10-19 - 00 - session-started-reactions-plan` (issues `session-started-notice`,
`session-start-advise`, `non-tool-advise-slot`). Decisions 1, 5 and 6 stand as first written; on
these points this amendment fixes them for the session's start:

- **`session-started` is a notice, fired at every session boundary.** Decision 1's notice list gains
  `session-started`: construction (a fresh session, `--resume`, and every headless, daemon or
  `/schedule` Firing), `/clear`, `/new`, a `/sessions` resume and `/fork` each fire it once.
  Delegates never fire it — a child is not a session start. Its payload carries `start`, one of
  `new | resume | clear | fork`.
- **For `session-started`, decision 6's non-tool slot is a fenced block inside the next user
  message, ahead of the prompt.** Decision 6's "fenced user-role message appended at the tail" is
  fixed, for this Moment, as no new message at all: the advice span rides inside the user message
  that opens the session's next Exchange, before the user's own text. That keeps the request one
  user message, never one placed after a tool result, so the Rejected row "a dedicated tail message
  for every advise" holds unchanged; the request prefix up to that message is untouched, as decision
  6 requires.
- **The span is ephemeral, as decision 6 states.** It lives in the live conversation only: it is
  stripped from the session record and dropped on resume, so a replay never re-reads it.
- **The user advise cell on `session-started` has its own admission arm.** Decision 5's arm proved
  the tool-result trailer, not this slot. A user `advise:` on `session-started` is refused at load,
  by a sentence naming it pending admission, until a D5-style arm passes for this path — an
  engine-origin handler returning a fixed neutral sentence at `session-started`, against Bypass under
  ADR 0009 (issue `session-advise-admission-arm`). Until then the slot is reachable only by
  engine-origin Go handlers, which is what the bench arms. *Superseded 2026-10-21 by
  `adr-0076-amend-1021`: the slot meets the structural bar a user cell needs, so the user
  `advise:` on `session-started` is admitted and the arm is evidence, not a gate.*
- **Advise entries start at the boundary, in the background.** The first request that carries a new
  user message waits only for the rest of each entry's timeout (decision 7's deadline), never for a
  fresh one.
- **Adoption before the first prompt fires for that session.** A repo `session-started` reaction
  (ADR 0104) adopted before the session's first prompt fires for the session it was adopted in;
  adopted after it, it fires from the next session boundary on.
