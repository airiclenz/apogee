---
title: "ADR 0076 amendment of 2026-10-27: a construction seed is not a live swap"
---

Ratified by the owner on 2026-10-27 for plan
`2026-10-27 - 00 - session-briefing-and-construction-seed-plan` (issues
`driver-boot-sequence-copied`, `session-lifecycle-scattered`). Decision A8 (`adr-0076-amend-0908`)
and `adr-0076-amend-1019` stand as first written; on these points this amendment fixes where a
session's first reaction lanes come from:

- **Seeding the lanes at construction is not a live swap.** `agent.New` and `agent.Resume` take a
  construction seed: both reaction lanes on `Config` (`Config.Observe`, and `Config.Sync` beside
  it), the delegation seat, the delegation target and the undo journal. Construction applies the
  seed in one fixed order and only then announces `session-started`, so the boundary's runs see
  the seeded lanes as the session's own. No session exists yet, no Exchange has run and nothing
  has been announced, so there is nothing to swap *from*: a seeded entry is armed at the boundary,
  never "newly armed" against a live session.
- **`SetReactions` stays the one live swap (A8).** Every change to the lanes of an Agent that
  already exists — a reload, a `/settings` row, an Adoption — goes through `SetReactions(gen)`, and
  only that path fires a `session-started` entry it newly arms. The seed adds no second swap door
  and no setter.
- **A seed is checked exactly as a swap is.** Construction validates the unscoped seed Generation
  first (`Generation.Validate`, `reactions.ValidateAll`, the reserved-id refusal) and only then
  scopes its Sync lane, in `SetReactions`' order. A seed `SetReactions` would refuse fails
  construction with a typed seed-refusal error that wraps the same underlying error; a refused
  construction announces nothing.
- **`Runner.Replace` before construction is the Driver's.** A8 made `SetReactions` the only caller
  of `Runner.Replace` on a live Agent. Before an Agent exists there is none to call it through, so
  a Driver whose seeded observe list differs from the one its Runner was built from validates the
  seeded lanes, then calls `Runner.Replace` itself, then calls `New`. `New` never calls
  `Runner.Replace`, and an observe list the validation refuses never reaches the Runner.
- **The Driver no longer runs the boot sequence.** Construction always announces
  `session-started` at its end, so the deferral (`Config.DeferSessionStart` and
  `Agent.AnnounceSessionStart`) is retired, and a Driver orders neither the lanes, nor the seat
  and target (ADR 0069 decision 6's 2026-10-27 note), against the announcement. Mode, effort and
  context files are not part of the seed: they stay post-construction replays. The undo journal
  rides the seed where the Driver holds it before construction; `run.Once`, which holds its record
  only after the Agent is built, keeps `SetJournal`, valid before the first Submit.
