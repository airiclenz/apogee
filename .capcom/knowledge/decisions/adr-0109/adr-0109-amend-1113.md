**A landed dial says when its tool list was cut short (2026-11-13,
`docs/plans/2026-11-13 - 00 - urgent-defects-and-doc-truth-plan.md`, item 11).** Decision 8's note
set — and its 2026-11-07 amendment's fifth note — is no longer fixed. Tool discovery stops at 64
pages or 512 tools and skips a tool whose schema is over 64 KiB; before, it did so without a word.
Now a dial that lands on a list cut short carries one clause after its sentence, naming each cause:

`mcp <server> connected — tool list cut short: stopped at 512 tools, skipped 2 tools with a schema over 64 KiB`

(`reconnected` for a replaced session). The causes are `stopped at 64 pages`, `stopped at 512 tools`
and `skipped <n> tools with a schema over 64 KiB`, in that order, worded by internal/mcp
(`Truncation.Causes`) so the numbers are the caps that applied. A cap counts only when the server
had more to give, so a server advertising exactly 512 tools is not cut short. The server still
connects on the tools it surfaced; nothing about the dial, the swap or the row changes.

Startup says the same as one loud startup notice per server,
`apogee: mcp server <server> — tool list cut short: …` (decision 11's connect is otherwise
unchanged: still all-or-nothing and fatal).
