Recorded 2026-11-18 by the owner, when the rule left a global coding-standards skill and needed a home in this repo. It restates decisions 2–4 as the standing test rule and corrects decision 2's description of stubllm, which has grown since.

**The rule.** A claim about the TUI, a streamed reply, an approval pane or a session record is asserted through `internal/tuitest` driving the real composition against `internal/stubllm`. A judgment claim — whether a pane reads right, whether a tone carries — is asserted through `internal/judge`, and only the judgment half: everything a cell can settle is settled by a cell. **Do not write an `httptest` upstream closure that stands in for the LLM: script stubllm.**

**Why.** Hand-rolled upstreams re-invented SSE framing, tool-call fragments and the usage shape per test and drifted from what real servers send. One strict scripted upstream makes the wire shape one reviewed thing, recordable from a real server, and an unmatched request fails the test instead of getting an improvised reply. The full reasoning and the how-to are in [docs/design/test-drivers.md](../../../../docs/design/test-drivers.md) — §Why, §Which driver observes which claim, and §Writing a new e2e test (step 2: "Script stubllm; never write a handler").

**Where it applies.** Every Go test that needs a model on the other end: the driven e2e tests in `cmd/apogee` (fixtures in `cmd/apogee/testdata/stubllm/`), the engine tests in `internal/agent` (through `stubllm.InProcess` and `Transport()`, no loopback socket), and any headless or daemon test run against an upstream. It does not cover an `httptest` server that is not the LLM — an MCP server, a fetch target, a proxy, a release feed — and it does not cover stubllm's own tests. The one documented exception is a test whose claim IS the wire bytes the client parses — `internal/provider/discovery_test.go` (test-drivers.md §Discovery) — where the parser must see payloads the stub would never write.

**What changed since decision 2.** Decision 2 calls stubllm "an OpenAI-compatible server". It now speaks both wires apogee speaks — `POST /v1/chat/completions` and the Anthropic `POST /v1/messages` — from one Script, serves discovery (`GET /v1/models`, `GET /props`), and also runs in-process with no port (`stubllm.InProcess`). The recorder (`stubllm record`) is still a chat-completions proxy only. The rule itself is unchanged.
