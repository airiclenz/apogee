---
title: "ADR 0035 amendment of 2026-11-23: a tool group folds on a follower, not on the next Turn's start"
refs: [docs/layout/tool-layout.md, internal/tui/transcript.go]
---

**Why now.** `adr-0035-amend-1120b` settled a finished block the moment the next Turn of its run
started. A model that works in bursts — one tool call per Turn, Turn after Turn, with no text
between them — saw its group fold after the first call and grow folded from then on: the reader
watched a one-line header tick up while the work they wanted to follow was hidden (issue
`tool-group-early-collapse`). A new Turn starting says the run is still busy with the same work,
not that it has moved on. The owner asked for the group to stay open through the burst and fold
only when something follows it (owner decisions 2026-11-23, plan
`docs/plans/2026-11-23 - 04 - tool-group-early-collapse-plan.md`).

**What this supersedes.**

- `adr-0035-amend-1120b` (a), "A block settles when the next Turn of its run starts", as a whole:
  a Turn boundary no longer marks or settles anything.
- `adr-0035-amend-1120b` (b)'s "It stays settled while the next Turn extends it" as a Turn-boundary
  rule: the stickiness now belongs to the reply-text settle in (b) below.
- `adr-0035-amend-1120c` (c)'s "the Turn boundary keeps it folded while the next Turn's call joins
  it", and the "Turn-boundary settle" it lists among what stands.

Everything else in `adr-0035-amend-1118`, `-1120`, `-1120b` and `-1120c` stands as written: what
touched means and that a touched group stays open as it grows, the wait on the user that opens a
block, every call being a tool group, the click on an auto-collapsed block that opens it alone and
writes nothing, the settings keys and their defaults.

**(a) A block settles on a follower, not on the next Turn's start (owner).** Under
`ui.tools-auto-collapse`, a finished, untouched foldable block — an umbrella (a group of one
included), a `✦ Sub-agents (N)` or `✦ Skill (N)` group — is settled, and folds, only when its run
has moved on past it:

- **reply or narration text follows it** — its own run's next streamed reply or narration has
  turned non-blank (below);
- **a later entry of its own run follows it** — a note, a user message, a further block that does
  not join it — every member of the block having finished; or
- **its run is over** — the Turn, for the conversation; the child, inside a sub-agent's run view.

A new Turn starting is not on that list. Consecutive Turns that each add a tool call, with nothing
committed between them, join one block (calls of two Turns merge while nothing is committed between
them), and that block stays open and growing for the whole burst. The same holds inside a delegated
run: only the child's own text or entries settle the child's block, and one run's text never
settles another run's block. A replayed block is still settled by construction.

**(b) Reply text folds the block as it first shows, and the fold is sticky (owner).** The fold
lands when the run's next streamed reply or narration text first turns non-blank — not when that
text commits as an entry — so the block folds beside the very text that moved past it. From then
on the block stays settled: a stream reset that discards the text, and a re-streamed call that then
joins the block, do not open it again; an umbrella shows its live verb on the folded header while
that call runs, a group its grown count. A member waiting on the user — a pending `ask_user`
question, a call held on its approval pane — still opens the block for as long as the wait lasts,
exactly as `adr-0035-amend-1120b` (b) said; once it is answered or decided, the block folds again.

**(c) Reasoning never folds (owner).** Reasoning or thinking output is not a follower: a run that
is only thinking after its calls returned leaves the block open. Blank or whitespace-only text is
not one either.

**(d) The size rule stays the only other fold (owner).** No new setting: the threshold is the
existing `ui.tools-fold-over`, counted in type rows, not calls. A live, untouched umbrella that
grows past it folds by the existing size rule, following `ui.tools-open` (default `false`, folded);
auto-collapse adds no size fold of its own. A Sub-agent or Skill group has no type rows, so it
folds on its own only on a follower.

All of it is TUI view state and paint: the settled mark is session-only, set on the run's last
entry when its text first turns non-blank, and never written to the session record or to config.
No engine, `domain` event or config-key change is made, so the engine stays Driver-neutral
(ADR 0031) and nothing reaches the model. Spec: `docs/layout/tool-layout.md`, "Fold states and
interaction".
