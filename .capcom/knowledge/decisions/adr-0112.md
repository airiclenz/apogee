Status: accepted (owner, 2026-11-11, ratified in `docs/plans/2026-11-11 - 01 - fence-escape-and-open-defects-plan.md`); amends ADR 0081 through `adr-0081-amend-1111` (the `connect(2) AF_UNIX` token is write-class); leaves ADR 0012's open-network default standing; decision 6 amended 2026-11-11 (abstract sockets under a network-deny bwrap box)
Amends: ADR 0081 (the 2026-09-22 note that classed `connect(2) AF_UNIX` "not write-class")

Auto's write fence does not cover a same-user service that spawns processes on request: a confined
command that reaches the user's systemd bus, dockerd or launchd runs code outside the box. Where a
backend can close the sockets those services listen on, it closes one fixed set — the user runtime
dir(s) and the docker and podman sockets — on bwrap always and on landlock from ABI 9; everything it
cannot close is disclosed as write-class, so the Auto startup notice words it on every backend and
ABI. Seatbelt discloses only, localhost TCP stays open under ADR 0012 and is disclosed in prose, and
the Windows token backend's posture is an open question. Read `adr-0112-context`,
`adr-0112-decision`, `adr-0112-rejected`, `adr-0112-consequences`.
