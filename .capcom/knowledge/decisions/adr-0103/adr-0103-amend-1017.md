---
title: "ADR 0103 amendment of 2026-10-17: on Windows the release may leave the journal for the sweep"
---

Decided in the live-session-watch run (docs/plans/archived/2026-10-17 - 03 - live-session-watch-plan.md). It qualifies decision 4. On Windows, Go opens a file without FILE_SHARE_DELETE, so while a watcher holds the journal open the owner's removal fails with a sharing violation. `Store.RemoveJournal` counts that as success and does not retry (`isRemoveSharingError`, internal/session/rename_windows.go). A retry would deadlock: the owner removes before it releases its hold, and the watcher closes only once it reads the hold free. The journal left behind has a free lock, so Live never lists it and the next startup sweep removes it. Only `GOOS=windows go vet` checks this path; no test runs it, and the CI Windows job does not cover `internal/session`.

> **Amended 2026-11-09 (docs/plans/2026-11-09 - 02 - windows-journal-remove-check-plan.md).** The CI Windows job now runs this path: its third step runs `internal/session`'s Windows-tagged tests (`TestWindows|TestAtomicWriteRetries`), among them `TestWindowsRemoveJournalUnderAWatcher`, which holds the journal open with the watcher's own `os.Open`, logs the errno the removal fails with, and pins that `RemoveJournal` returns nil, Live skips the leftover and the sweep removes it once the watcher closes; the rest of `internal/session` still does not run there. `isRemoveSharingError` now accepts `ERROR_SHARING_VIOLATION` only, no longer the `ERROR_ACCESS_DENIED` it took from the rename predicate: a removal an ACL refuses is reported to the owner (the "session journal stopped" notice) rather than hidden, and a read-only journal is still removed, since `os.Remove` clears that attribute itself.
