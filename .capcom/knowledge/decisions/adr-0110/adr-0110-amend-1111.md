title: "ADR 0110 amendment of 2026-11-11: a deleted or missing file drops out of changed files"
refs: [docs/layout/side-panel-layout.md, internal/sidepanel/sidepanel.go, internal/tui/sidepanel.go]
---

**Why now.** The changed-files section only ever grew: a successful `delete_file` folded as one
more write, so the file it removed stayed listed, and a file removed any other way — a `terminal`
`rm`, a `move_file` source, `/undo` — stayed listed too, since no Event reports it (issue
`panel-deleted-file-entry`). The owner ratified the fix on 2026-11-11 ("Deleted rows" in the
ratified design calls of plan
[`2026-11-11 - 03 - junction-save-and-panel-deleted-file-plan.md`](../../../../docs/plans/2026-11-11%20-%2003%20-%20junction-save-and-panel-deleted-file-plan.md)).

**What this amends.** Decision 4's "Every section renders from engine Events", for the
changed-files section only; decision 10's changed-files live rule, "once the session has written a
file"; and decision 13's changed-file row, which counted a deletion as a change. Each is to be read
as this amendment restates it.

**(a) A deletion removes a row (decisions 13 and 4).** A successful `delete_file` result removes its
path from the changed-files fold at every scope, top level and Run view alike, whichever
run deleted it; a failed one changes nothing. A later write lists the path again, ordered by
that write and counted from it on. The removal is part of the Driver-neutral fold, so watch mode
and a resumed session drop the row as the live session did: a resume replays a stored `delete_file`
card as the same removal.

**(b) A file gone from disk is hidden (decision 4).** The TUI re-checks the listed paths against the
disk, off the Update goroutine, at each Turn's end and on the git-status cadence, never at paint
and under no deadline. A path the disk reports as not existing is hidden from the painted section,
its header count, its navigation stops and its click targets until a later re-check finds it again
or a write to it lands; any other stat failure keeps the row. This re-check is TUI state, not a
fold of Events: the Event-folded rows stay the same for every Driver, and another Driver may filter
them the same way or not at all.

**(c) The section is live while a row remains (decision 10).** In `auto` the changed-files section
shows while it has at least one row left after (a) and (b); a session whose every listed file was
deleted or is gone shows none.

**(d) Terminal writes stay unseen (decision 13).** A file written through the `terminal` tool is
still not shown. Only its disappearance is seen, through (b), and only for a file an apogee file
tool had already listed.
