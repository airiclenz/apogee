---
title: "ADR 0110 amendment of 2026-11-10: a set width leaves the transcript 60 columns"
refs: [docs/layout/side-panel-layout.md, internal/tui/sidepanel.go]
---

**Why now.** The separator drag stopped a full transcript floor short of the window edge: under
`auto` the transcript never went below 100 columns, so in a 160-column window the panel could not
grow past 59 however far it was dragged (issue `transcript-min-width-floor`, owner 2026-11-10). The
one floor did two jobs: the gate, whether the column docks at all, and the ceiling on how wide the
user may make it once docked. The gate is an automatic choice and should not squeeze the
transcript; a width the user set is a deliberate trade of transcript for panel and should not be
held to the same number. The owner ratified the split on 2026-11-10 ("Transcript minimum" and "Who
chose the width" in the ratified design calls of plan
[`2026-11-10 - 01 - panel-and-tool-shape-fixes-plan.md`](../../../../docs/plans/2026-11-10%20-%2001%20-%20panel-and-tool-shape-fixes-plan.md)).

**What this supersedes.** `adr-0110-amend-1108` (a)'s upper limit, "at most the window less the
transcript floor (100 columns in `auto`, 80 in `on`) less the scroll-bar column", and the same
limit as `adr-0110-amend-1109b` (a) restates it, for a set width only. `adr-0110-amend-1109b` (b)'s
"Between 137 and 145 columns in `auto` the default-width column docks clamped narrower than 44"
stands for an unset width and is superseded for a set one. Each is to be read as this amendment
restates it.

**(a) A set width leaves the transcript 60 columns.** A width the user set — by a separator drag,
`/panel width <n>`, a `/settings` edit, or `ui.side-panel.width` written in config — is clamped to
at least 24 columns and at most the window less 60 columns less the scroll-bar column, one value
under `auto` and `on`. 60 columns is the narrowest transcript at which the transcript, the prompt
box and tool blocks still render whole. A separator drag always clamps as set, so it stops exactly
60 columns and the scroll bar short of the window's left edge.

**(b) An unset width keeps the gate floor.** With `ui.side-panel.width` unset (the default 44,
including after a double-click on the separator, `/panel width reset` or a deleted key), the column
is clamped as before: at most the window less the show mode's transcript floor (100 columns in
`auto`, 80 in `on`) less the scroll-bar column, so the default column docks clamped narrower than
44 between 137 and 145 columns in `auto`.

**(c) The gate is unchanged.** The column still docks from 137 columns in `auto` and 117 in `on`,
computed with the 36-column gate width of `adr-0110-amend-1109b` (b), whatever width the user set.
The 60-column minimum is the drag's and the layout's limit, never the gate's: a set width never
docks the column on a window narrower than the gate.

**(d) The clamp still never writes.** A stored width outside the limits is clamped when the layout
is computed and never rewritten by the clamp, so a terminal that grows back paints the stored width
again.
