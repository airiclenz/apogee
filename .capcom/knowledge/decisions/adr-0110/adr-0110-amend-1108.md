---
title: "ADR 0110 amendment of 2026-11-08: the side panel's width is user-set by dragging its separator"
---

**Why now.** The 36-column width of Decision 7 is too narrow for long file paths on a wide
terminal and too wide when the transcript needs the room, and the owner asked for the width to be
set by hand the way `capcom ui` lets its divider be dragged (issue `side-panel-resize`, owner
2026-11-08). The rejected option "Proportional or user-set width" turned down a user-set width
"for no use asked for"; that use is now asked for. A proportional width stays rejected: it would
re-wrap the transcript on every resize step inside the gate.

**What this supersedes.** Decision 6's "the column's width and presence change only when the
terminal crosses the width gate, or on the user's toggle", Decision 7's "The column is 36 columns
wide", the Decision headline's "fixed column" whose width "changes only on a deliberate event"
(now read with (d) below), the summary's "fixed-width column" that "appears or vanishes only when
the terminal crosses the width gate or the user toggles it" (`adr-0110`), the considered option
"Proportional or user-set width" for its user-set half, and the consequence "The cached frame
re-keys only on a gate crossing or a toggle". Each is to be read as this amendment restates it.

**(a) A user-set width, 36 by default.** The column is 36 columns wide by default, and the user
may set its width. Its limits: at least 24 columns, and at most the window less the transcript
floor (100 columns in `auto`, 80 in `on`) less the scroll-bar column. A stored width outside them
is clamped when the layout is computed and never rewritten by the clamp, so a terminal that grows
back paints the stored width again. The show/hide gate is unchanged: it is still computed with
the default 36 (137 columns in `auto`, 117 in `on`), whatever width the user set.

> **Amended 2026-11-09 (`adr-0110-amend-1109b`).** The default width is 44 and the gate keeps a
> 36-column gate width of its own; the grip of (b) is the separator and the one column right of it.

**(b) Dragging the separator.** A left-button press on the panel's separator column, or on the
gutter column to its right, on any row above the transcript slot's bottom, starts a resize drag.
The separator keeps its grab offset from the pointer, and the panel and the transcript re-wrap
live on every column it moves, like `capcom ui`'s divider. While the drag is active the separator
is drawn in the accent tone, bold. A double-click on the separator (two presses within 500 ms)
resets the width to 36 and starts no drag. The hover shape is unchanged: no resize cursor, since
ADR 0106 admits only `default`, `text` and `pointer`. A drag starts nowhere else, and the
separator has no key binding.

**(c) Persisted as `ui.side-panel.width`.** The width is the global key `ui.side-panel.width`, in
columns, default 36; zero means unset and resolves to 36. A drag writes it once, on release, and
only when the width differs from the one at the press. It is editable in `/settings`, and
`/panel width <n>` sets it and `/panel width reset` resets it to 36, beside Decision 8's
`/panel on|off|auto` and `/panel pin|unpin|hide <section>`. In watch mode the drag and
`/panel width` are inert, as `/panel` already is there.

**(d) Decision 6, restated.** The column's presence still changes only when the terminal crosses
the width gate or on the user's toggle, and its width only on a deliberate act of the user's: a
drag, a double-click, `/panel width` or a `/settings` edit (and, within the clamp of (a), a
terminal resize). Sections still grow, shrink, appear and hide inside it, so live content never
re-wraps the transcript. The cached frame re-keys on a gate crossing, a toggle, or a change of
the painted width.

**(e) The one exception to "mouse motion never repaints".** A held-button mouse motion while a
separator drag is active relayouts the frame when the computed width changed; every other mouse
motion still never repaints. The rule lives in `internal/tui/model.go` (`settle`, `settleFrame`),
`internal/tui/doc.go` and `TestMouseMotionNeverRepaints`, ratified by plan
[`2026-09-16 - 00 - host-config-and-tui-deepening-plan.md`](../../../../docs/plans/archived/2026-09-16%20-%2000%20-%20host-config-and-tui-deepening-plan.md)
item 18; this exception narrows that rule and does not supersede it. ADR 0106 is not amended: its
Decision 5 covers button-less motion only, and the drag is held-button motion.
