---
title: "ADR 0108 amendment of 2026-11-18: a refused repository shows a git refused marker and says why once"
---

**Why now.** Decision 3 says "A refused repository gets no action, as it gets no git segment." The
second half made a refusal silent: the status host answered a repository refused for its own
command-valued config exactly as it answered no repository at all, so the footer dropped the git
segment and `/git` said `no git here`, with nothing to say what was refused or why (issue
`git-refusal-silent-footer`; plan `docs/plans/2026-11-18 - 00 - git-refusal-silent-footer-plan.md`,
items 4–5). `adr-0012-amend-1118` narrows what refuses — a repo-local merge driver alone no longer
does — and this note records what the footer does with what still refuses.

**Decision 3's last sentences now read:** a refused repository still gets no action, but it keeps a
segment that says so.

- **The marker.** The status host reports a refused repository distinctly from a missing one
  (`gitexec.IsCommandConfigRefusal`), and the footer's git segment reads `git refused` in the
  footer's error tone, at the segment's usual priority, instead of vanishing. Outside a work tree
  the segment is still absent.
- **The one-time note.** The first read that lands a refusal, or a different one, posts one routine
  transcript note: the refusal sentence, naming the key, then `Move the key to your global git config
  if you trust it.` A refusal that stands is not noted again on later reads. A refusal of a watched
  session's workspace shows the marker and posts no note.
- **`/git` answers with the sentence.** `/git`, and a click on the marker, answer with that same
  refusal sentence instead of opening the picker or saying `no git here`; `no git here` stays the
  answer where there is no repository at all.
- **Still no action.** Nothing in the refused case reaches the picker, and every action still runs
  through gitexec, so a refused repository stays refused, as Decision 3 says. A repository carrying
  only a repo-local merge driver is not refused: it shows its ordinary segment and offers every
  action, and `rebase onto upstream` alone is refused there with gitexec's merge-driver sentence,
  in its failure note.

The layout rule is in `layout.md`, "The footer's upstream slot" → "The git state."; the manual's
in `docs/manual/commands.md` §Git actions.
