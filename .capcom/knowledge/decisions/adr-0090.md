---
title: Workflow stages are enterable views
---

Status: accepted
Amends: ADR 0063 (D4 — a level of the view stack may be a workflow stage, which is not a run), and reverses the engine-run workflows plan's item 43 rule that the workflow block "paints one way and never collapses" and that "a head with many runs has no run view"

> Note (2026-10-03): the Mechanism layer this ADR refers to was removed; ADR 0076 (Reactions) replaces it. Read the Mechanism-specific parts as historical.

A workflow block shows one row per stage from the start, and each row opens that stage's work in the
transcript slot as a stage view, or as its one item's run view. Every item run gets its own run
head, a `fan_out` card lists its items, the rows reopen after a resume, and item runs no longer
paint in the conversation. Read `adr-0090-context`, `adr-0090-decision`, `adr-0090-rejected`, then
`adr-0090-consequences`.
