---
title: A server entry may name fallback servers, and a failed seat falls over one-way
---

Status: accepted; decision 3 amended by `adr-0105-amend-1102` (an Anthropic `api_error` counts as 500)
Amends: ADR 0028 (decision 3 — a fallback rehome is the one switch allowed mid-Turn, `adr-0028-amend-1102`), ADR 0085 (its future Note on fallback pools is realised here, `adr-0085-amend-1102`), ADR 0045 (decision 4 — a fallen-over Sub-agents seat latches its fallback, `adr-0045-amend-1102`), ADR 0075 (decision 4 — a twenty-sixth line kind, `upstream_switched`, `adr-0075-amend-1102`)

A `servers:` entry may name an ordered `fallback:` list. When the entry's server fails mid-Turn
with a fault that would abandon the Turn today, apogee probes the primary for up to
`fallback-after:` (default `2m`). If it is still down, apogee rehomes the seat to the first live
fallback and resends the failed request, so the Turn continues. The move is one-way and per seat,
every Driver gets it, and an `upstream_switched` Event reports it. A config without `fallback:`
behaves exactly as before. Read `adr-0105-context`, `adr-0105-decision`, `adr-0105-rejected`,
`adr-0105-consequences`, then `adr-0105-amend-1102`.
