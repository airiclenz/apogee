---
title: "ADR 0057 amendment of 2026-11-02: a host's own tool set takes a fallback's roster through its builder"
---

Decided with the Server fallback follow-ups (docs/plans/2026-11-02 - 01 - fallback-followups-plan.md, item 7). It amends the first bound (`adr-0057-bounds`) for one exception: a host that injects its tool set together with a builder for it.

The first bound keeps an injected `Config.Tools` as the host's set verbatim, so the engine re-composes a roster only for a set it composed itself. A Server fallback rehome (ADR 0105 decision 5) binds the fallback model's profile mid-Turn, and an unattended run (headless, the daemon, a session-raised Firing) under `sub-agents-choice: model` or `sub-agents-context: on` hands the engine a set of its own (`firingSeatTools`), because the engine cannot publish those `sub_agent` arguments itself. Such a run kept the primary model's roster after the move for the rest of the run, where the same run on the engine's set took the fallback's.

**A host that injects its set may hand over a builder for it, and a rehome rebuilds through that builder.** `Config.ToolsForRoster` is a builder the host supplies beside `Config.Tools`. At a rehome, an Agent whose set is the host's calls it with the fallback profile's roster axis on its own goroutine at the request boundary, and offers the set it returns from the first request after the move. The host rebuilds its own set, so the engine still builds nothing over a host set, and with no builder an injected set stays as it is, as the first bound says. The Firing composition is the only host that supplies one. It re-runs `firingSeatTools` over the run's final Config with only the profile's roster replaced. The TUI supplies none, because it settles its own roster at the Turn boundary (`adr-0105-amend-1102c`).

The builder applies only to the Agent the host built. A sub-agent never inherits it: a child running at the rehome keeps the set it was spawned with, including a `tools:`-narrowed subset. A child spawned after the rehome narrows the rebuilt set its parent then holds. The builder is consulted at a rehome only: `Rebind` and `SetProfile` behave as before.
