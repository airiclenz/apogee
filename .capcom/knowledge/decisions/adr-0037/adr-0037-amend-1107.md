---
title: "ADR 0037 amendment of 2026-11-07: MCP servers reconnect one by one, off the keystroke"
---

**MCP servers now reconnect one by one, off the keystroke (ADR 0109).** This record's live-apply
promise stands for every other key. For the `mcp-servers` key, and for the MCP part of the
`url-safety` rows, three of its decisions are superseded:

- **Decision 1**: "same keystroke" and "no second moment" no longer hold. A save dials an added or
  changed server in the background. A finished dial joins the tool registry at the next idle point,
  and its outcome arrives as a transcript note per server. A removal or a deny still takes effect on
  the keystroke: that server's tools are refused at once.
- **Decision 7**: the whole-set validate-then-commit is replaced by a per-server one. A failed
  re-dial keeps that server's old session, and the healthy servers are untouched. The row text
  becomes `saved — live apply failed: <server>: …`, and the note
  `mcp reconnect failed: <server>: … — previous connection kept`. **Startup connect failure stays
  fatal**, as before.
- **Decision 8**: the row annotations are no longer exactly three. The `mcp-servers` row adds
  `reconnecting MCP…` while its dials run.

Decision 2's single registry-mutation path is kept: every commit is still one idle-only
`SwapTools`. Read ADR 0109 for the design.
