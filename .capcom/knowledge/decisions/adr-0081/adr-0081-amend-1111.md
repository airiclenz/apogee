---
title: "ADR 0081 amendment of 2026-11-11: connect(2) AF_UNIX is write-class, and the box masks the runtime dir"
---

**Why now.** The 2026-11-10 code audit (issue `fence-escape-local-spawner`) showed that a reachable
pathname AF_UNIX socket is not only a network-egress gap: a same-user service that spawns processes
on request — the user's systemd over `/run/user/<uid>/bus`, dockerd over `/var/run/docker.sock` —
runs code outside the box for whoever connects. ADR 0112 sets the fence's posture on those services.

**1. `connect(2) AF_UNIX` is write-class.** This supersedes the Decision's 2026-09-22 note where it
says "The token is not write-class, so `probe.CapabilityLine` words it and `probe.ResidualNotice`
filters it out: no host gains a startup banner for it." `probe.ResidualNotice` now words the token at
Auto start with its spawn-elsewhere consequence, so every host this backend fences on gains that
notice. The rest of the note stands: the token names the pathname-socket reachability the
`--ro-bind / /` root carries into the box.

**2. The box no longer carries every socket.** Per ADR 0112 decision 3, the box puts `--tmpfs` over
the user runtime dir(s), re-binding only the ssh-agent and gpg-agent sockets beneath it, and masks
the system docker and podman sockets. The token is still disclosed, because every other pathname
socket stays reachable.

**Pinned by** the drift tests that pin the disclosed residual tokens and the startup notice's
wording, and by the bwrap argv test and `confinetest` row that items 5, 7 and 8 of
`docs/plans/2026-11-11 - 01 - fence-escape-and-open-defects-plan.md` add.
