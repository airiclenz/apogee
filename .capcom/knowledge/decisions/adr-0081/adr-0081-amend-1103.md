---
title: "ADR 0081 amendment of 2026-11-03: the bwrap backend runs in its own PID namespace"
---

**Why now.** The 2026-11-03 code audit (`docs/reviews/code-audit-2026-11-03.md`, High) found the
Decision's "never `--unshare-pid`" opened an escape out of the box. `--proc /proc` without a PID
namespace mounts a procfs that lists the host's processes, so a same-uid confined command can open
`/proc/<apogee-pid>/root/…` — a path resolved against apogee's own, unconfined mount namespace — and
write outside the box through it, and where `kernel.yama.ptrace_scope` is 0 it can read apogee's
memory too. The box bounds where a child may write; this read-write view of the host's root defeated
it.

**1. Every run carries `--unshare-pid`.** It joins the fixed prefix beside `--die-with-parent`
(`namespaceArgv`, `internal/platform/namespace_linux.go`), so the child's procfs is its own PID
namespace's and names no host process. This supersedes the Decision's "never `--unshare-pid`"
sentence; its "never `--new-session`" half stands. The construction probe launches the same flag line,
so a host that grants the user namespace but refuses CLONE_NEWPID answers the probe with a refusal
(`CauseLaunchRefused`) and the selector moves to its next rung, as for any other refused launch.

**2. The teardown kill was never at risk.** The rejected reason — a PID namespace "would hide the
child's process group from the teardown kill" — does not hold: a process group belongs to the host,
and the namespace's processes keep their host PIDs and the group they inherited, so the negative-PID
kill reaches bwrap, its reaper and the command alike.

**3. The setsid residual no longer holds on this backend.** bwrap's reaper is the namespace's pid 1,
and when it dies — killed by the group kill, or exiting once the command has exited — the kernel kills
every process left in the namespace. A descendant that called setsid to leave the run's group, the
accepted POSIX residual of the contract's §2.4, therefore dies with the run on both the cancel and the
clean-exit path. Landlock and seatbelt runs keep the residual.

**Pinned by** `TestNamespaceArgv` (the flag is present in every box), `TestNamespaceHidesHostProcesses`
(a confined child reads no host status through `/proc/<pid>` and writes no host file through
`/proc/<pid>/root`) and `TestNamespaceTeardownLeavesNoSurvivor` (no confined sleep, setsid escapee
included, survives a cancelled or a cleanly exited run, looked for in the host's `/proc`), all in
`internal/platform/namespace_linux_test.go`. The contract's §2 namespace paragraph, §2.4 residual and
Linux done-criteria carry the same dated amendment.
