---
title: Linux falls back to a namespace fence through bwrap
---

Status: accepted; the Decision's "never `--unshare-pid`" superseded by `adr-0081-amend-1103` (every run gets its own PID namespace); the Decision's 2026-09-22 "not write-class" note superseded by `adr-0081-amend-1111` (2026-11-11, ADR 0112: `connect(2) AF_UNIX` is write-class and worded at Auto start, and the box masks the user runtime dir and the docker and podman sockets)
Amends: ADR 0042 §4 (Linux gains the same bounded exception macOS has), ADR 0056 D2 (the kill-on-denial signature learns EROFS)

On Linux the confiner tries landlock first and falls back to a `namespace` backend that runs
commands under `bwrap`, a second bounded exception to ADR 0042. The box shape is fixed, the probe
launches bwrap for real, any run-time failure is `ErrConfinementUnavailable`, never an unfenced run,
EROFS joins the kill-on-denial signature, and `Unavailable` says why. Read `adr-0081-context`,
`adr-0081-decision`, `adr-0081-rejected`, `adr-0081-consequences`, then `adr-0081-amend-1103` and
`adr-0081-amend-1111`.
