---
title: "ADR 0060 amendment of 2026-11-02: the reasoning object's shape picks the dialect"
refs: [internal/provider/discovery.go]
---

Amends decisions 1 and 2: a `/v1/models` entry's `reasoning` object is the effort tell by the KEYS it carries, not by its presence. The field name is shared by servers that read different request dialects — Splash advertises `{"thinks": true, "efforts": [...], "default": "medium"}` there and reads the dial through `chat_template_kwargs`, silently ignoring OpenRouter's `reasoning: {effort}` — so a shared field name is not proof of OpenRouter's dialect, and a wrong guess drops the user's effort without any error. The rule, in precedence order (`decodeReasoning`, `internal/provider/discovery.go`):

- **OpenRouter's shape** — an object carrying `supported_efforts` or `default_effort` selects the `reasoning` dialect with that vocabulary and default, whatever Splash keys it also carries: the OpenRouter keys win a mixed object.
- **Splash's shape** — otherwise an object carrying `thinks`, `efforts` or `default` selects the `kwargs` dialect with its `efforts` as the reported levels and `default` as the reported default. An explicit `thinks: false` is the server's own answer that the model has no dial: it means unsupported, and it is final — discovery does NOT fall through to the `/props` template tell for that model.
- **No tell** — any other object, a bare `{}` included, states nothing, exactly like an absent, null or malformed value; only then does discovery fall through to the `/props` `chat_template` tell of decision 1.

A key whose value is JSON null counts as absent. Decision 2's list of sighted dialects is unchanged: Splash's shape is a second detection source for the `kwargs` dialect, not a fourth dialect. Rejected: reading any non-null `reasoning` object as OpenRouter's (the rule this replaces, which sent Splash a wire it ignores), and letting `thinks: false` fall through to `/props` (it would override the server's explicit answer with a template guess).
