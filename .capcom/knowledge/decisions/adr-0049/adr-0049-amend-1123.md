---
title: "ADR 0049 amendment of 2026-11-23: the git config-key catalogue is one leaf package"
---

`adr-0049-amend-1103` and `adr-0049-amend-1114` name the git config keys a repo-local `git config`
write names `.git/config` for, and place the string behind them in `internal/security`
(`GitCommandConfigNameSource` and the suffix composing `GitCommandConfigName`, in `shellwrites.go`).
This note moves that string, and nothing else (item 5 of
`docs/plans/2026-11-23 - 01 - git-repository-state-plan.md`).

**Where the catalogue lives.** `internal/gitconfigkeys` is the single definition of:

- `Source`: the probe source, every config name whose value is a program git executes. It is the
  string `GitCommandConfigNameSource` held, byte for byte.
- `WriteViewSuffix`, and `WriteViewSource` (`Source` widened by it): the keys only the shell write
  view names.
- `MergeDriverSource`: the `merge.<x>.driver` pattern `internal/gitexec` neutralises per call
  (`adr-0012-amend-1118`). `Source` is composed from it, so the key is spelled once.
- `ValueIsBenign`: the values that name no program after all (a git-boolean `core.fsmonitor`, a
  `protocol.allow` or `protocol.ext.allow` of `never`, a `submodule.<n>.update` mode without a
  leading `!`), with the git-boolean spellings it reads.

The package imports the standard library only. `internal/security` compiles
`GitCommandConfigName` from `WriteViewSource`, and `internal/gitexec` compiles `CommandConfigName`
from `Source` and its merge-driver pattern from `MergeDriverSource`; neither file restates a key.
`security.GitCommandConfigNameSource` and `security.gitConfigValueIsBenign` no longer exist.

**What this supersedes.** Only the placement: `adr-0049-amend-1114`'s "Probe source" paragraph and
"What stays clear" paragraph, and `adr-0049-amend-1103`'s "Which keys" paragraph, read
`GitCommandConfigNameSource` and `gitConfigValueIsBenign` as living in `internal/security`. Read
them as `gitconfigkeys.Source` and `gitconfigkeys.ValueIsBenign`. `adr-0012-amend-1118`'s
`security.GitCommandConfigNameSource` is the same string under its new name.

**Why a third package.** `internal/gitexec` imports `internal/security` (the exec fence), so the
string could sit in `security` or below both, never in `gitexec`. It sat in `security`, which made a
path-and-command guard package the owner of a fact about git's config and left the merge-driver
pattern restated in `gitexec`. A leaf below both gives the catalogue one home (owner, 2026-11-23).

**What does not change.** Which keys are refused, neutralised or benign; the rule that splits them
(a key apogee's own git can reach goes in the probe source, a key the git hosts already neutralise
goes in the write view's suffix only); `gitexec.CommandConfigName.String()`, which the tools tests
hand to `git config --get-regexp`; and which merge-driver names can be neutralised, which stays
`gitexec`'s rule (`neutralisableMergeDriver`). `internal/gitconfigkeys`' `TestSourceIsUnchanged`
pins the source and the suffix against literals copied from the commit before the move.
