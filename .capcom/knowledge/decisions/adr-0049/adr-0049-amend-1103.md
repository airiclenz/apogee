---
title: "ADR 0049 amendment of 2026-11-03: a repo-local `git config` write of a key git runs unprompted names .git/config"
---

Note 0914 says of the shell write view that "Nothing is synthesised": `git config -f .git/config
user.name x` is refused because `.git/config` is an operand, never because the guard inferred it.
That sentence no longer holds for one case, and has not since commit af21d0be (2026-09-22). This
note records the case and widens it (item 6 of `docs/plans/2026-11-03 - 00 - code-audit-fixes-plan.md`,
issue `git-config-fsmonitor-write`).

**What is synthesised.** A `git config` invocation that writes the repository's own config — no
`--global`, `--system`, `-f` / `--file` operand, and no read form (`--get`, `--list`, …) — and
names a key from `security.GitCommandConfigName` (matched lowered, as git canonicalises the
name) gains `.git/config` as a write target (`gitTargets`, `gitConfigWritesCommandKey` in
`internal/security/shellwrites.go`), so `write-git-control-plane` hard-refuses it. Its operands
alone (`filter.x.clean cmd`) never spell the control-plane path the rule matches.

**Which keys.** The pattern is gitexec's command-valued set (`GitCommandConfigNameSource`: a
driver, helper, editor, pager, proxy, …) plus the keys git runs, or reads more config through,
without being asked: `core.hooksPath` (since af21d0be), and from 2026-11-03 `core.fsmonitor`,
`interactive.diffFilter`, `include.path` and `includeIf.<cond>.path`. A planted script registered
as one of them runs unconfined the next time the operator's shell, editor or `git status` touches
the repository; an include path pulls in a config file that can carry any of the others. The
additions live only in the write view's suffix, never in `GitCommandConfigNameSource`: gitexec's
probe would otherwise cost a repository its git tools for keys its hardening options already
neutralise or its `--includes` listing already follows.

**What stays clear.** A `core.fsmonitor` whose value word is a git boolean (`true` / `false` /
`yes` / `no` / `on` / `off` / `1` / `0`, any case) is no control-plane write: `true` turns on git's
builtin daemon and `false` turns the hook off, so neither names a workspace program, while
`git config core.fsmonitor ./x` hard-refuses. `alias.*` stays allowed (owner call, 2026-11-03):
git runs an alias only when it is typed. A `--global` write lands in the operator's file, outside
the rule, as before.
