Status: accepted (2026-10-14). Decided in the `settings-typing-filter` grilling; it reverses the
2026-08-20 amendment's "/settings does not filter" and replaces decision 6's filter *line*.

**Context.** The 2026-08-20 amendment left `/settings` unfiltered for two reasons: backspace there
arms a reset, and a filter field cost a `lineEditor` (+40 KB on a `Model` copied every `Update`).
The second is gone — a field is now a `copyOnWriteField`, an 8-byte pointer. Meanwhile the two
filtering panes had drifted from each other and from `layout.md`: a paste landed in the prompt draft
under the pane, the caret showed while `/sessions` was renaming, the selection jumped by index as
the filter changed, and matching ran over every cell, so a row's live state (`· running`, `· 5m
ago`) decided what a filter found. The owner wants every list to behave one way.

**Decision.** One filter contract for every *searchable* list — `/settings`, `/sessions` and the
picker kinds that list things:

1. **Which lists filter.** A list you search filters; a question you answer does not. The workflow
   boundary, key migration, sub-agents migration and adoption pickers are questions with two or
   three fixed answers and stop filtering, like the approval and ask_user menus.
2. **Typing.** Every printable key types into the filter; there is no activation key (2026-08-06).
   Backspace trims the filter while it holds text. On an empty filter backspace keeps whatever the
   pane gave it before — an armed reset in `/settings`, nothing elsewhere. `/settings` adds
   **delete (⌦)** as a second reset key that works with or without a filter, so a filtered view
   never has to be destroyed to reset a row.
3. **esc closes** the pane, filter and all. Backspace is the filter's only undo.
4. **Match what the row says it is, never its live state.** Case-insensitive substring, no ranking,
   no reordering, no highlight of the matched characters. Each pane names its matched text:
   `/settings` the key path and its section heading (a heading match keeps its whole section; a
   section stays while any of its rows match); a picker row its name and gloss; the fork picker the
   prompt text; `/sessions` the title cell with its qualifiers. Values, source marks, notes, stats,
   ages, counts, spend and status marks are excluded.
5. **The filter shows on the pane's title row** — `Title · filter: mo▌` — only while it holds text,
   and never on a line of its own: no row is taken from the list and nothing moves on the first
   key. The caret shows only in the state where typing reaches the filter. A sub-step that keeps the
   list on screen keeps the filter text (no caret); one that replaces the list hides it. When the
   row is too narrow, the title's tail gives way first, then the hidden-rows count; the filter
   stays whole, or shows its caret end behind a leading `…`.
6. **Selection.** When the filter changes, the highlight stays on its row if that row still
   matches, else moves to the first match; when the filter empties it stays where it is. ↑/↓ walk
   and wrap over the matches only.
7. **Zero matches** paint one faint, unselectable row, `no <noun> matches "<filter>"` (control
   characters stripped), with the pane's own noun. A pane's own empty-state note (a workspace with
   no sessions) wins over it.
8. **Legend.** `type to filter · …` while the filter is empty. Once it holds text, `type to filter`
   drops and `⌫ trim` appears (`/settings` also shows `⌦ reset`, or `⌦ remove` on a rule row). At
   zero matches the legend keeps only `⌫ trim`, the keys that change the row set (`/sessions`' `^a`)
   and the pane's `esc`.
9. **A paste is typing**: it lands in the filter, folded onto one line, wherever typed keys would.
   In a sub-mode with its own field (a `/sessions` rename) it lands in that field; in a confirm it
   is dropped. It never reaches the prompt draft under a pane.
10. **The filter survives a pane's sub-steps** (`/settings`' enum list, value field, text editor,
    armed reset, `Save to:`); keys inside a sub-step go to that step, never to the filter.

**Rejected.** The filter in the prompt box (the box would show text ⏎ does not send, its arrows
would mean list moves, and its renderer would paint another pane's state). Esc clearing the filter
before closing (one key meaning two things on one surface only). Matching every cell (live state
makes the result depend on the moment). Filtering a two-answer question.

**Consequences.** Decision 6 stands for *where the filter is stated* (one place) but no longer for
its line, its two blanks or its budget claim. The 2026-08-20 amendment's `listCursor` /
`listSurface` split stands; `/settings` now carries a filter and the four question kinds no longer
do. A pane joining the list family must say which side of rule 1 it is on and, if it filters, what
its matched text and its noun are.
