---
title: Project config execution keys are adoption-gated entries
---

Status: accepted; decisions 4 and 11 amended by `adr-0104-amend-1018` (the argv and `env:` file search, the full `env:` display)
Amends: ADR 0076 (decision 10 — the repo layer's execution keys, and "later layers overriding by key"), ADR 0096 (decision 6 — `mcp-servers:` and `reactions:` leave global-only; decision 4 — Adoption pins structured entries)

A Project config may propose `mcp-servers:` and `reactions:` entries. Each is inert until the user
adopts it; Adoption pins a canonical form of what the entry runs or where it sends data, plus the
content of every project file its command names, so an edit to either asks again. A repo entry never
replaces the user's own, starts with a minimal environment, fires only inside its own Project root,
and a repo `run:` goes through the workspace exec fence. Read `adr-0104-context`,
`adr-0104-decision`, `adr-0104-rejected`, `adr-0104-consequences`, then `adr-0104-amend-1018`.
