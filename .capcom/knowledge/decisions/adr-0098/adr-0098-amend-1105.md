---
title: "ADR 0098 amendment of 2026-11-05: publish places the v1 placeholder tag"
---

**Why now.** ADR 0107 makes v1.0.0 releasable by tagging a self-retracting placeholder — the
highest burned v1.x version, v1.8.1 today — on v1.0.0's own commit. The owner chose to have
`publish` place that tag (plan `2026-11-05 - 00 - v1-placeholder-retraction-plan`, ratified
2026-11-05). Decisions 3 and 4 list `publish`'s steps as pushing, waiting for the CI tag and
publishing the channels, and `publish` has so far never created a tag of its own; this amends
both, for the placeholder tag only.

**1. `publish` creates exactly one tag, the placeholder, after `release`.** Its steps run `tag`,
`release`, `placeholder`, `homebrew`, `scoop`, `winget`, `smoke`. The `placeholder` step is
pending only for a release from v1.0.0 up to the placeholder, and only while origin lacks the
placeholder as an annotated tag; it is reported done ("not needed") for every other release.
Before it tags, it checks that go.mod at the release tag retracts exactly the burned versions,
the placeholder among them, so the placeholder retracts itself; it never moves or replaces a
placeholder, and a local one that a failed push left on the release's commit is pushed again. A
release that would need the placeholder is refused before anything changes when go.mod at
`HEAD` fails the same check — the "refuses before changing anything" contract holds.

**2. CI still creates every release tag.** The tag-on-version-bump workflow stays the one tagger
of releases: the `tag` step only waits for it, as Decision 3 says. The placeholder is not a
release: it has no GitHub release, no assets and no channel entry.

**3. The build never reads the placeholder as its version.** The asset build deletes every burned
version's tag from its clone first, because `go build` would otherwise stamp the placeholder,
which sits on the same commit, as the binary's module version.

**4. Decision 4's probes gain one.** `status` reports the placeholder probe beside the others, and
the `smoke` step adds a Go module proxy check: the exact release version reported retracted
fails, an `@latest` that resolves elsewhere only warns, since the proxy caches.
