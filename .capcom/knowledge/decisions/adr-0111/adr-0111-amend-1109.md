---
title: "ADR 0111 amendment of 2026-11-09: an MCP server that dies mid-session reads disconnected (lost)"
---

**Why now.** The record shipped knowing that an MCP server dying mid-session went unseen: the
consequence "A mid-session server death is still not detected (`internal/mcp` has no session
watcher); the Event reports only what the dial lifecycle knows", parked as issue
`mcp-session-death-undetected`. A crashed stdio server or a dropped connection kept reading
`connected` in `/mcp` and the panel, and its tools stayed on the menu until a call failed. The
owner ratified the shape on 2026-11-09 (plan
[`2026-11-09 - 00 - mcp-test-gaps-and-session-death-plan.md`](../../../../docs/plans/2026-11-09%20-%2000%20-%20mcp-test-gaps-and-session-death-plan.md)).

**What this supersedes.** That consequence, which this amendment answers; and Decision 8's
`disconnected` "(with the reason)", whose reasons were only the deliberate `removed` and `denied`
and now gain `lost`. Decisions 9 and 10 hold unchanged; (c) and (d) below say how a lost server
reads in them.

**(a) A death is `disconnected`, reason `lost`.** No new phase: a session that ends on its own
while apogee still holds it posts one `MCPServerEvent` `disconnected` whose reason is `lost` and
whose `cause` is why it ended, redacted of the endpoint and de-labelled the way a failed dial's
cause is (`kept` is false). Any connection the SDK ends on its own reads `lost`: the server
process exited or crashed, the connection dropped, a message broke the transport (one past the
4 MiB cap, a failed POST, a stream that will not reconnect). A stdio server's clean exit reads
`exit status 0`; any other ending without an error reads `connection closed`. The cause is
untrusted server text, escape-stripped where a Driver renders it, as every other cause is.

**(b) The watcher, and no deadline.** `internal/mcp` parks one watcher per live session on the
SDK's `ClientSession.Wait()` and reports, once, a session that ends while its Client is neither
retired nor closed (`Client.Lost`, `Client.LostCause`); a deliberate retire or close never reports.
The composition root (`liveMCP` in `cmd/apogee/wire_mcp.go`) watches each installed session. There
is no keep-alive ping and no fixed deadline: the SDK's `ClientOptions.KeepAlive` was rejected, since
it kills a session on its first missed ping under a tight timeout, which a slow box would trip.

**(c) The server is dropped like a removed one, and never re-dialled on its own.** A lost server is
retired at once, so a call to one of its tools answers that the server is not connected, and its
tools leave the menu at the next idle-point commit (ADR 0109). Nothing reconnects it: Decision 9's
"reconnecting stays on the settings `mcp-servers` row" holds. The loss marks the server failed, so
the `/settings` round trip re-dials it as it re-dials every failed server — unless a dial already
queued, running or waiting for its commit is bringing it back, which then decides its state.

**(d) What each reader sees.** The model is not told: no notice, no Reaction. `/mcp` reads
`disconnected (lost)` with no tools and the cause wrapped beneath the row, as a failed server's is.
The panel's `mcp` section keeps the row (`name · disconnected`, no count) and, being `auto`, shows
itself (Decision 10). The transcript gains one display-only line,
`mcp server <name> disconnected (lost): <cause>`, written only for a live loss — never for the
startup seed or a watched journal's Event, and never kept in the session record. Because the
Event rides the stream and the journal (Decision 8), a watch and the journal read the same state.

**(e) The limit.** The watcher sees a connection end only while there is a connection to end:
stdio and SSE always, streamable-http while its standalone stream is up. A streamable-http server
without one — it answers the standalone GET with `405` or another tolerated refusal — holds no
connection between calls, so its death is noticed only on its next call: the failed POST ends the
session, which then reads `disconnected (lost)`. That is documented, not fixed; a keep-alive prober
for such servers, `list_changed` (`ToolListChangedHandler`) and MCP in `apogee headless` or the
daemon stay out of scope.
