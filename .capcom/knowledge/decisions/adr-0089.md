---
title: A workflow may run in the background and wakes the agent when it ends
---

Status: accepted
Amends: ADR 0086 (its "we keep the blocking model and do not build asynchronous delegation" now binds `sub_agent` alone), ADR 0007 (an Exchange may open on an engine note rather than a user message)

A Workflow may run in the background while the conversation goes on, at the Parallel-agents width
minus one; its end sends a one-line finish note that wakes an idle agent, and a model shown the
switch also gets the `workflow` tool to check, stop or message it. `sub_agent` stays blocking, as
ADR 0086 decided. Read `adr-0089-context`, `adr-0089-decision`, `adr-0089-rejected`, then
`adr-0089-consequences`.
